### 이 날 배운 것 (다시 만난다)
- ★**"배포됐다"는 "된다"는 뜻이 아니다.** Rules API 는 **버킷 존재를 검사하지 않는다** —
  없는 버킷에도 규칙을 붙여 주고 "완료"라고 답한다. 한나절을 여기서 헤맸다
- ★**결제(Blaze)와 API 활성화는 별개다.** Blaze 인데도 Storage API 가 꺼져 있어 403 이 났다
- ★`.firebasestorage.app` / `.appspot.com` 은 **구글 소유 도메인**이라 직접 못 만든다.
  Firebase 콘솔의 '시작하기'만 만들 수 있다
- ★**users 읽기는 규칙으로 못 조인다.** 두 번 시도해 두 번 다 콜드스타트를 깼다
  (닉네임이 전부 '머피' / 인기 캐릭터·룸 사라짐). 데이터를 나눠야 한다
- ★**OAuth 스크립트를 여러 개 띄우지 말 것.** 4개가 포트 9005 를 경쟁해서 옛 프로세스가
  클릭을 받아 "실패했어요"가 떴다. 새로 띄우기 전에 반드시 이전 것을 죽인다
- ★방 안에 **탭으로 반응해야 하는 것**을 얹으면 조이스틱 예외 목록에 반드시 추가한다.
  안 넣으면 PC 에서는 되고 **폰에서만 안 된다**(touchstart preventDefault 가 합성 click 을 취소)

## 앞으로 쓰는 법
- 배포할 때마다 **맨 위에 한 줄** 추가한다
- ★버전은 이제 **세 곳**이다: `index.html` 의 `_SW_V` · `sw.js` 의 `murpy-vNNN` · **`version.txt`**.
  `version.txt` 는 옛 화면 자가복구가 읽는 기준값이라, 안 올리면 복구가 안 돈다.
- `sw` 번호는 `index.html` 의 `_SW_V` 와 `sw.js` 의 `murpy-vNNN` 이 같아야 한다.
  어긋나면 새 코드가 폰에 안 간다 — `murpy.app/?diag=1` 로 확인
- 영향 범위에 **"에셋만"** 이라고 쓸 수 있으면 되돌리기가 쉽다. 그게 아니면 뭘 건드렸는지 적는다
