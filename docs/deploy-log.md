# 배포 로그

> 대표 지시(2026-08-24): **"너무 고치면 어디에 영향받는지 모르게 되니 배포 로그를 쓰자."**
>
> 규칙 — 한 줄에 하나. `sw 버전 · 커밋 · 무엇을 · 어디에 영향`.
> **영향 범위를 반드시 적는다.** 나중에 "이게 왜 이렇게 됐지"를 되짚는 게 이 문서의 목적이다.
> 상세한 이유는 커밋 메시지에 있다 — 여기는 색인이다.

## 앞으로 쓰는 법
- 배포할 때마다 **맨 위에 한 줄** 추가한다
- `sw` 번호는 `index.html` 의 `_SW_V` 와 `sw.js` 의 `murpy-vNNN` 이 같아야 한다.
  어긋나면 새 코드가 폰에 안 간다 — `murpy.app/?diag=1` 로 확인
- 영향 범위에 **"에셋만"** 이라고 쓸 수 있으면 되돌리기가 쉽다. 그게 아니면 뭘 건드렸는지 적는다
