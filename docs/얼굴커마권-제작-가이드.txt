■ 핵심 원칙 (재진 때 확정된 것 — 어기면 사고)
 · **AI 시트를 통째로 쓰지 않는다.** 목 아래는 base(char/walk.png) 원본 그대로,
   목 위(머리)만 AI 시트에서 이식한다. AI 몸통을 쓰면 실루엣이 base 와 미세하게
   달라 human 옷 전체가 어긋난다. (대표 8-26 확정)
 · 컷 라인은 고정값이 아니라 셀마다 실측한다 — face_graft.py 가 자동으로 한다.
 · 노이즈 제거는 자동 판정 금지 — 얼굴은 개성이라 기계가 판단 못 한다.
   자리를 눈으로 찍어 그 네모 구간만 되돌린다(face_denoise.py).

■ 파이프라인 (고객 1명 = 아래 6단계)

 1) [대표] 고객 얼굴 시트 생성 — 제미나이(나노바나나)로 12칸 워크 시트.
    재진 원본: Desktop/머피브랜딩/.../얼굴커스터마이징/조재진.png (704×1504)
    ★재진 때 실제로 통한 방법 (대표 9-03 공유 — 원문 그대로):
      첨부 1 = ★생성용 민머리 베이스 시트 (walk.png 아님!)
        Desktop\머피브랜딩\머피월드 캐릭터\커스터마이징 3차\기본의상\남_기본의상_생성용.png
        — 3×4 걸음 시트인데 **머리카락이 없고**(민머리) 기본 속옷 차림, 마젠타 단색 배경.
          민머리라야 AI 가 기존 헤어와 안 싸우고 고객 머리카락을 새로 그린다.
          (여캐 고객이 오면 여_기본의상_생성용 버전이 필요 — 없으면 먼저 만들 것)
      첨부 2 = 고객 정면 셀카 6장 정도 (학습용 — 각도·표정 조금씩 다르게)
        ★판매 흐름에선 **본인 얼굴인증이 승인된 셀카**를 쓴다(대표 9-03) —
          남의 얼굴로 커마권을 쓰는 것을 인증 기능이 막아준다.
      프롬프트 원문 (대표 확정 + 9-03 피부톤 줄 추가):
        "도트스프라이트 시트의 구조와 톤앤매너를 유지한채 실물사람의 얼굴 및
         머리카락으로 도트캐릭터시트를 만들어줘 캐릭터의 다른 기본 옷, 걸음걸이,
         3*4구조는 절대 바꾸지말고 오로지 얼굴만 저사람버젼으로 만들어줘.
         피부톤은 기본캐릭터시트를 유지해줘"
      ※마지막 줄이 중요한 이유: 얼굴이 base 피부색으로 나와야 skin_bake 가
        t1~t6 여섯 톤을 깨끗하게 구울 수 있다(굽기는 base 주황 피부색 기준).
    ※몸통은 어차피 2)~3)에서 base 로 갈아끼우므로, 생성물에서 중요한 건 **머리
      (얼굴·헤어)가 12칸 전부 일정**한가다.

 1-b) [대표] 다듬기 — 한 방에 안 나온다. 재진 때도 첫 생성 뒤 **같은 대화에서**
    결함 칸을 "N열 M번째" 좌표로 짚어 부분 수정을 시켰다 (대표 9-03 실례):
      "지금 4열의 2,3번째 캐릭터 시트 눈썹만 얇아. 눈썹 굵은 버전으로 저거 두 개 통일해줘"
      "눈썹이 정지 때는 평평하고 이동 때는 세워지는데, 이런 일관성을 깨는 게 아니라
       3열의 2번째 캐릭터처럼 살짝 눈썹 끝으로 갈수록 위로 올라가는 느낌으로 세팅해줘"
    요령: ①칸 좌표(열·번째)로 짚는다 ②고칠 방향은 **잘 나온 칸을 기준**으로 준다
    ("3열 2번째처럼") ③"일관성을 깨지 말라"를 명시한다.
    재진 실적: 첫 생성 + 이런 부분 수정 **2회**로 완성("딱 재진이 얼굴 나왔음").
    → 자동화 견적도 고객당 제미나이 호출 3회 안팎(약 $0.12)으로 잡으면 된다.
    ※같은 대화 안에서 다듬는 건 OK. 반면 **결함 있는 결과물을 새 대화에 레퍼런스로
      재투입하는 건 금지** — 결함이 스타일로 학습돼 대물림된다(한글 타이틀 사고와 동일).

 2) [클로드] 규격 정렬 — 받은 시트를 우리 규격 423×896(셀 141×224, 3열×4행)으로
    재추출. (재진: 704×1504 → 423×896)

 3) [클로드] 얼굴 이식 —
      python tools/face_graft.py --face char/faces/{고객id}_src.png --out char/faces/{고객id}.png
    base 몸통 + AI 머리로 구워진다. 콘솔에 셀별 컷라인(y)이 찍히니 눈으로 확인.

 4) [클로드] 노이즈 정리(필요시) — 대표가 "여기 이상하다" 찍어주면
      python tools/face_denoise.py --face char/faces/{고객id}_src.png --base char/walk.png --rect y0 y1 x0 x1 --rows 행번호
    후 3)을 다시 돌린다.

 4.5) [클로드] 피부톤 6종 굽기 — 기존 피부톤 선택과 호환돼야 한다(대표 9-03).
    tools/skin_bake.py 로 char/skin/face_{고객id}_t1,t2,t4,t5,t6.png 생성
    (재진 전례: face_jaejin_t1~t6 존재. t3=base 원색이라 파일 없음, t7 폐기).
    머리카락은 시트에 포함(fixedHair)이라 헤어 톤 굽기는 따로 없다.

 5) [클로드] 앱 등록 — index.html 두 곳:
    · _CHAR_BODIES.{고객id} = { name, skinBase:'face_{고객id}', src:'char/faces/{고객id}.png?v=1',
        cw:141, ch:224, wearable:true, fixedHair:true, kin:'human', tag:'커마',
        defaultTop/'defaultBottom', owner:'{고객 uid}', desc }
      — kin:'human' 이라 human 옷 전부 그대로 입는다. fixedHair 로 헤어 슬롯 잠금.
      owner 를 넣으면 그 uid 만 이 몸통이 보인다.
    · SQ_MG_EYES.{고객id} = { y, x:[좌,우] } — 무궁화꽃 하트눈 좌표. 정면 셀에서
      눈 위치를 실측(셀 대비 비율). 안 넣으면 human 값이 쓰여 눈이 어긋난다.

 6) [대표] 검수·승인 — 합성 미리보기(기본 옷 + 대표 옷 2~3벌 갈아입혀 캡처)를
    보고 승인해야 배포. 등록 전 검수 필수 규칙 그대로.

■ 자동화 로드맵 (대표 9-03: "결제해서 사람들이 쓰는 상품이 되어야 한다")

 Phase 1 — 도구 자동화 (지금 가능 · 선결 = 제미나이 API 결제 연결)
   tools/face_pipeline.py (예정): 셀카 폴더 + 고객id + 성별 넣으면
   [생성용 민머리 시트 + 셀카 6장 + 위 프롬프트]로 제미나이 API 호출 →
   423×896 리그리드 → face_graft → skin_bake 6종 → 검수용 합성 미리보기까지 한 번에.
   대표는 셀카 받고 명령 한 줄 + 승인만. 장당 약 $0.04(gemini-2.5-flash-image),
   재생성 몇 번 해도 몇백 원. ★무료 등급은 이미지 429 — AI Studio 카드 연결이 선결.

 Phase 2 — 앱 안 반자동 (유저 결제 → 서버 생성 → 대표 원탭 승인 → 지급)
   · 셀카 수급: 기존 본인 얼굴인증 흐름 재사용 — 인증 승인된 정면 셀카 6장
   · 결제: PG 없음 → 당장은 머피(크레딧) 판매 또는 이체+수동 확정. PG 후 19,900원
   · 생성: Cloud Functions 가 서버 키로 제미나이 호출 → 리그리드·graft·bake
   · 검수: 관리자 승인 큐(미리보기 보고 원탭 승인 → 지급). 품질 편차 때문에
     승인 단계는 유지 권장 — 19,900원짜리가 이상하게 나가면 환불 사고다
   · ★제일 큰 개조 = 몸통의 데이터화. 지금 _CHAR_BODIES 는 index.html 하드코딩이라
     고객마다 앱 배포가 필요하다. 커스텀 몸통을 Storage 시트 + Firestore 메타로
     읽는 동적 로딩을 만들어야 배포 없이 지급된다.

 Phase 3 — 완전 자동: 자동 QC(12칸 일관성·base 실루엣 diff·캔버스 채움률) 통과분은
   즉시 지급, 실패분만 재생성→대표 검수. 환불 규정 필요.
