# 머피월드 에셋 생성 AI — 자체 학습 로드맵 (B안)

*작성 2026-07-31. 대표 지시로 "추후 착수용" 근거 문서. 지금은 C안(정합·검증 도구)을 먼저 다진다.*

---

## 0. 한 줄 요약

**GPT·나노바나나 API를 붙이는 게 아니라, 오픈 웨이트 모델(SD/FLUX)에 머피 화풍 LoRA를
학습시키고 ControlNet으로 자세를 못 박는다.** 금액은 10만원 안쪽에서 시작 가능하고,
진짜 비용은 엔지니어링 시간이다.

---

## 1. 왜 이 문서가 필요한가 — 지금 막힌 지점

우리가 반복해서 겪는 결함은 전부 한 뿌리다:

> **AI가 프레임마다 몸을 다르게 그린다.**

- 헤어 시트의 몸이 1px 어긋나 차분에 '유령'이 잡힌다
- 회색 후드집업 **우 col2** 만 다리 자세가 base 와 달라 몸 윤곽선이 옷으로 오인됐다
- 세미리프컷 정면 뒷머리가 잘리고, 검은 머리는 차분이 0이 되어 통째로 누락된다

프롬프트로는 못 막는다("포즈와 형태를 그대로 유지한 채" 같은 문장을 넣어도 확률적이다).
**생성 단계에서 자세를 강제로 고정해야** 사라지는 문제다. 그게 ControlNet 이다.

---

## 2. 업계가 실제로 쓰는 구조 (2026-07 조사)

| 층 | 내용 |
|---|---|
| 기반 모델 | **Stable Diffusion (SD1.5 / SDXL)** 또는 **FLUX** — 오픈 웨이트, 자체 호스팅 |
| 화풍 학습 | **LoRA** 파인튜닝 (이미지 10~30장) |
| 자세 제어 | **ControlNet** — 포즈·구도를 고정한 채 생성 |
| 워크플로우 | **ComfyUI** 또는 자체 파이프라인 |

- 공개 픽셀아트 LoRA만 Civitai 에 551개. SDXL 대표 = `nerijs/pixel-art-xl`
- **에테르AI 가 이 구조라는 증거**: "IP GPU 학습 — 이미지 20~80장 올리면 화풍 학습".
  남의 API 를 쓰면 GPU 학습을 상품으로 팔 수 없다.
- PixelLab 은 기반 비공개지만 "모델이 클라우드 GPU 에서 돌아간다" = 자체 호스팅.

## 3. 비용 실측 (2026-07 기준)

### LoRA 학습 (1회)
| 방식 | 비용 | 시간 |
|---|---|---|
| GPU 직접 렌트 | **약 $0.5** | RTX 4090 1시간 |
| 호스팅(fal.ai 등) | **$2~5/회** | 자동 (1000스텝 $2.40) |

필요 학습 이미지 **10~30장** — 우리는 이미 충분하다(walk.png, 아이템 시트, 검수 렌더).

### GPU 시간당
| GPU | Vast.ai | RunPod |
|---|---|---|
| RTX 4090 | $0.34~0.50 | $0.34 (커뮤니티) |
| A100 80GB | $0.50~0.80 | $1.39 |
| H100 | $0.90~1.87 | $2.89 |

**픽셀아트는 해상도가 작아 4090 이면 충분하다.**

### 우리 예상
- **실험 단계**: 학습 10~20회 시행착오 → **$40~100 (5~15만원)**. ControlNet 은 기성 모델이라 학습 불필요.
- **운영 단계**: 서버리스(생성할 때만 GPU 기동). 스프라이트 1장 몇 초 → 장당 수십 원.
  상용 이미지 API(장당 $0.04~0.2)보다 오히려 싸다.

## 4. 우리가 이미 갖고 있는 것 (= 남들보다 앞선 지점)

1. **고정 스켈레톤** `char/walk.png` · `walk_female.png` — ControlNet 조건으로 그대로 쓸 수 있다.
   4방향 × 3프레임 자세가 이미 확정돼 있다.
2. **base 영역지도** `char/base_regions.py` — 덮어야 할 곳 / 건드리면 안 될 곳
3. **검증 도구 일습** — 이게 핵심 자산이다:
   - `verify_col_consistency.py` 3열 모양 일치(걸음 깜빡임)
   - `diag_walk_frames.py` 12프레임 펼쳐보기
   - `diag_stray_pixels.py` 걸음 프레임 불순물
   - `diag_holes.py` 내부 구멍(귀 분리)
   - `diag_combo.py` 앱과 같은 z 순서 조합 렌더
   - `diag_face_drift.py` 두상/얼굴 드리프트
4. **후처리·복원** `restore_from_source.py`, `borrow_frame.py`, `cover_all_frames.py`,
   `nukki_solid.py`, `build_outfit_layer.py`

> ★**검증 기준이 없으면 LoRA 를 학습시켜도 좋아졌는지 나빠졌는지 모른다.**
> 실제로 2026-07-31 에 지표를 잘못 재서 "고쳤다"고 잘못 보고한 적이 있다.
> C 안(도구)을 먼저 다지는 이유가 이것이다.

## 5. 착수 순서 (B안)

**전제: C안 도구가 안정화되어 "좋아졌다/나빠졌다"를 수치로 판정할 수 있을 것.**

1. **데이터셋 정리** — 머피 화풍 학습용 10~30장 선별 + 캡션.
   이미 만든 아이템 시트와 검수 렌더를 쓴다. 워터마크(✦) 없는 것만.
2. **ControlNet 조건 만들기** — `walk.png` 에서 자세 조건 이미지 생성(윤곽/뎁스/포즈 중 택).
   픽셀아트는 선이 굵어 canny·lineart 계열이 유력.
3. **LoRA 1차 학습** — FLUX 또는 SDXL. RTX 4090 렌트, 1~3시간.
4. **판정** — 기존 검증 도구를 그대로 돌린다. 특히 3열 일관성·프레임 드리프트.
   **사람 눈 확인은 대표가 최종**(수치가 좋아도 그림이 나쁘면 되돌린다 — 실제로 그런 적 있다).
5. **반복** — 스텝 수·학습률·데이터 조정. 시행착오 10~20회를 예산에 넣는다.
6. **파이프라인 결합** — 생성 → 정규화 → 차분 추출 → 검증 → 리터치.
   생성만 갈아끼우면 뒷단은 지금 것 그대로 쓴다.

## 6. 하지 말 것

- **망가진 프레임을 이미지 생성 AI 에게 다시 그리라고 하기.**
  결함의 원인이 "AI 가 매번 다르게 그림"인데 같은 도구로 고치면 또 다른 드리프트가 생긴다.
  → 같은 시트의 멀쩡한 프레임에서 빌려오는 게 맞다(`borrow_frame.py`).
- **Claude API 로 픽셀 편집을 기대하기.** 이미지를 보고 좌표로 짚어줄 수는 있어도
  픽셀을 그리지는 못한다. 스튜디오에 붙어 있는 Claude 는 **한국어 지시를 연산으로 번역**하는 용도다.
- **검증 없이 모델부터 바꾸기.** 4번을 건너뛰면 개선인지 회귀인지 알 수 없다.
