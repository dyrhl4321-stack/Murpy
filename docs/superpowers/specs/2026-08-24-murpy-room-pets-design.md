# 머피월드 방 펫 — 설계서

작성 2026-08-24. 대표 브레인스토밍으로 확정한 내용이다. 구현 계획은 별도 plan 문서로 뺀다.

## 왜 만드는가

대표가 유료 펫 팩(`Top-Down-Pet-Pack v1.1`)을 샀다. 기존 고양이 '도로'를 나노바나나로 뽑으려다
품이 너무 들어 작업을 앞당기려고 산 것이다. 목표는 방에 장식을 하나 더 놓는 게 아니라
**진짜 반려동물을 키우는 감각**이다.

> "머피월드에서 계속 들락날락할 때마다 바뀌는 게 아니라 진짜 실제로 고양이 키우는 거마냥
> 6-7시간 잘 때도 있고. 고양이랑 강아지랑 또 다르니까."
> "이러한 아주 디테일적인 요소들이 결국 입소문을 부름."

이 문장이 이 설계의 기준선이다. **판단이 갈릴 때는 "진짜 키우는 것 같은가"로 결정한다.**

## 대표가 확정한 것

| 항목 | 결정 |
|---|---|
| 돌봄 깊이 | **가볍게 돌봄** — 밥·쓰다듬기는 있고, 방치해도 병들거나 사라지지 않는다 |
| 획득 | 고양이·강아지는 **머피로 구매**. 방에 나와 있는 펫은 **동시 1마리** |
| 공룡 | **이스터에그 보상으로만.** 돈으로 못 산다 = 유일하게 못 사는 펫 |
| 손님 시야 | 손님에게도 **나와 똑같은 모습**이 보인다. 손님은 구경만 (밥 못 줌) |
| 공룡 마리수 | 펫 1마리 + **어슬렁 무리 최대 N마리**. N은 실측으로 확정 (아래 성능 절) |

## 에셋

### 산 것 — `Top-Down-Pet-Pack v1.1`

`Desktop/머피브랜딩/머피월드 캐릭터/커스터마이징 3차/외부에셋테스트/펫에셋/`

- 셀 **32×32**. 모든 시트가 32의 배수라 자를 필요가 없다.
- 고양이 3종(Black·Fat·Milky) / 강아지 3종(Brown·Small·White)
- 동작 9종. 이동계(STANDING·WALKING·RUNNING·EATING·LICKING·OBSERVING·SNIFFING·PLAYFUL)는
  **행 1~4 = 앞·좌·뒤·우**. SITTING·LAYING 은 전환 애니(서기↔앉기)가 홀수 행에 끼어 있고
  그 사이가 정지 idle 이다. SLEEPING 은 좌/우 두 방향뿐이다.
- 소품: `PET_PROPS`(밥그릇 4색 · 빈 것/찬 것 · 뼈다귀 · 생선뼈), `CAT_TOWER` 3색, `DOG_HOUSE` 3색

**쓰는 것만 옮긴다.** 9종 전부를 앱에 싣지 않는다 — 아래 행동표에 나오는 것만
`char/pets/{종}_{동작}.png` 로 복사하고 나머지는 저장소에 넣지 않는다.

### 공룡 — 손이 더 간다

- 기존 `s2608_dino.png` = 94×105 **8프레임 APNG**(둥가둥가). 프레임 간격 균등 120ms.
  → `char/build_dino_sheet.py` 로 가로 시트를 뽑아 뒀다. **그림은 한 픽셀도 안 바꿨다.**
  CSS `steps(8)` + `0.96s` 로 지금과 완전히 같게 재생된다.
- 걷기 4방향 원본은 `Desktop/.../펫움직임구현/공룡 걸음걸이 {측면,정면,뒷면}.png`.
  형광초록 배경에 **격자 없이** 놓여 있고 **프레임마다 크기와 발높이가 다르다.**
  → 누끼 → 프레임별 바운딩박스 → **발선(바닥) 기준 정렬** → 32px 격자 시트로 재조립.
  대표가 미리 짚은 "옆걸음이 좀 안 맞을 수도"가 이 지점이다. 측면이 3프레임뿐이라
  다른 방향(4프레임)과 재생 길이를 맞춰야 한다.

### 표시 크기

방 타일 `t = 방폭/16`. **펫 높이 = t × 1.3** 으로 시작한다(캐릭터는 t × 3.3).
`image-rendering:pixelated` 로 확대한다. **이 배율은 대표가 실기기에서 보고 정한다** —
상수 하나(`MW_PET_SCALE`)로 빼서 한 줄로 조절 가능하게 둔다.

## 상태를 어떻게 유지하는가 — 하루 일과표

**펫의 현재 행동을 DB에 저장하지 않는다.** 저장하면 앱이 꺼져 있는 동안 시간이 멈추고,
손님에게 보여주려면 실시간 동기화가 필요하고, 몇 분마다 쓰기가 돈다. 셋 다 피한다.

대신 `hash(uid + 펫id + YYYYMMDD)` 를 씨앗으로 **오늘 하루치 일과표를 그 자리에서 계산**한다.

```
하루 = 10분 칸 144개
1. 씨앗으로 의사난수 생성기를 만든다 (같은 입력 → 항상 같은 결과)
2. 종별 수면 시간을 덩어리로 배치한다 (고양이 14~16시간을 3~4덩어리, 강아지 8~10시간을 2덩어리)
3. 남은 칸을 종별 행동 가중치로 채운다
4. 지금 시각 → 칸 번호 → 그 칸의 행동
```

- **앱을 껐다 켜도 시간이 그대로 흐른다.** 오후에 끄고 저녁에 켜면 그 사이 낮잠이 끝나 있다
- **손님도 같은 함수·같은 시각을 본다** → 동기화 코드가 필요 없다
- **씨앗에 날짜가 들어가 매일 다른 일과표**다. 어제와 같은 시각에 자지 않는다
- 칸 안에서의 세부 동작(걷다가 앉았다가)은 앱이 열려 있는 동안만 자체적으로 굴린다.
  이건 저장 대상이 아니다 — 나갔다 오면 달라져도 된다. **큰 흐름(자는 중인가)만 일과표가 정한다.**

### 개입은 저장한다

유저가 실제로 뭘 했을 때만 쓰기가 일어난다. 이 값들이 일과표를 덮어쓴다.

```
users/{uid}.pet = {
  id:'cat_milky',      // 지금 나와 있는 펫
  name:'도로',          // 이름 (기본값 = 종 이름)
  mode:'free',         // free | follow | stay
  fedAt:<ts>,          // 밥 준 시각 — 이후 몇 시간은 배부름(먹기 행동이 안 나옴)
  patAt:<ts>           // 쓰다듬은 시각 — 자고 있었으면 잠깐 깬다
}
users/{uid}.pets = ['cat_milky','dino']   // 산 것·얻은 것 전부 (보관함)
```

## 종별 차이 — 이게 핵심이다

에셋에 이미 차이가 들어 있으므로 그대로 쓴다.

| | 고양이 | 강아지 | 공룡 |
|---|---|---|---|
| 하루 수면 | **14~16시간**, 3~4덩어리 (한 번에 3~5시간) | **8~10시간**, 2덩어리 | 잠 에셋 없음 → 대신 둥가둥가 |
| 고유 행동 | 그루밍(핥기) · 가만히 관찰 · 식빵(웅크려 자기) | 냄새 맡기 · 꼬리 흔들기 · 장난치기 | 걷기 · 둥가둥가 |
| 이동 | 적게 움직인다. **높은 데를 좋아함** | 자주 돌아다닌다. **사람 근처를 맴돔** | 느리게 어슬렁 |
| 가구 | 침대 · 탁자 · 식탁 · 캣타워 **위로 올라감** | 침대 · 소파까지. 개집으로 들어감 | 못 올라감 |
| 불렀을 때 | **가끔 무시한다** (follow 여도 3번에 1번은 안 옴) | 바로 온다 | 느리게 온다 |

"고양이는 불러도 잘 안 온다"는 코드 한 줄이지만, 이런 게 대표가 말한 '입소문 부르는 디테일'이다.
**구현하다 시간이 없으면 다른 걸 자르고 이건 남긴다.**

## 가구 위 올라가기

방 시스템에 이미 **상판(`surface`)** 과 **상판 깊이(`topDepth`)** 가 있다 — 소품을 얹는 자리다.
여기에 `petPerch` 태그만 더한다.

- `petPerch:'cat'` — 고양이만 (탁자 · 식탁 · 책상 · 캣타워)
- `petPerch:'all'` — 고양이·강아지 (침대 · 소파 · 러그)
- 자유 행동 중 잠 칸에 들어가면 **가장 가까운 perch 를 목적지로** 삼는다. 없으면 바닥에서 잔다
- 올라가 있는 동안 z = 그 가구 z + 1. 안 그러면 가구 뒤에 파묻힌다
- 올라간 상태에서는 걷기가 아니라 앉기/눕기/자기만 나온다

## UX — 펫을 누르면

캐릭터 링 메뉴(`#mw-charmenu`)와 **같은 물건을 재사용**한다.
★단, **문구는 새로 쓴다.** 예전에 스쿼드 게스트 시트를 게임에 통째로 재사용했다가
"실명으로 적어주세요"가 뜬 적이 있다.

- **자유** — 일과표대로 산다 (기본)
- **따라오기** — 내 뒤 한두 칸을 따라온다. 자는 칸이어도 따라온다 (고양이는 가끔 무시)
- **여기 있어** — 그 자리에 앉아 있는다
- **밥 주기** — 방에 밥그릇이 있어야 활성. 그릇이 찬 그림으로 바뀌고 펫이 걸어가서 먹는다
- **쓰다듬기** — 하트 하나. 자고 있었으면 잠깐 깼다가 다시 잔다
- **이름 짓기 / 보관하기**

내 펫에만 뜬다. 손님이 남의 펫을 누르면 이름과 종만 보이는 작은 말풍선이 뜬다.

## 성능 — 렉을 구조로 막는다

대표 지시: **"근데 그렇다면 렉 안 걸리게 해야 함."** 지금 공룡을 10마리 넘게 놓은 방이 있다.

### 안 건드리는 것

**가만히 있는 공룡은 코드 한 줄도 안 건드린다.** 지금처럼 `<img>` APNG 그대로다.
스프라이트로 바꾸면 `mwFurnHtml` 이 `<img>` 라서 **꾸미기 배치 드래그가 깨진다**
(`char/animate_dino.py` 주석에 이미 적혀 있는 이유다).

### 새로 얹는 것의 규칙

1. **`left`/`top` 금지. `transform: translate3d` 만.** 레이아웃 재계산 0회
2. **타이머는 방 전체에 하나.** 마리마다 `setInterval` 을 걸지 않는다
3. **JS 는 프레임마다 안 돈다.** 걷는 그림은 CSS `steps` 다. JS 는 도착 순간에만 깨어난다
4. **동시에 안 움직인다.** 드라이버가 한 번에 한 마리씩 돌아가며 출발시킨다
5. **안 보이면 완전히 멈춘다.** 방을 나가거나 앱이 백그라운드로 가면 드라이버를 끈다
6. **자동 감속.** 방에 들어간 직후 실제 프레임 시간을 재서 기준보다 느리면 움직이는 마리수를 줄인다

★스프라이트 재생은 `steps(N)` + `to: -N칸`. `-（N-1)칸` 으로 잡으면 프레임이 밀려
**한 마리가 여러 마리처럼 보인다**(전에 두 세션 헤맨 함정).

### 마리수 상한

**펫 1마리 + 어슬렁 N마리.** N 기본값 **3**, 실측 결과에 따라 최대 5까지 올린다.
4마리째부터 놓인 공룡은 지금과 똑같은 완전 정지 장식이다.

측정 도구 = **`dino-perf.html`** (배포됨). 가만히 있는 공룡 수 / 움직이는 공룡 수 / 이동 주기를
바꿔가며 rAF 프레임 시간을 10초간 잰다. 대표 폰에서 아래 4가지를 재고 N을 확정한다.

| # | 가만히 | 움직임 | 무엇을 아는가 |
|---|---|---|---|
| 1 | 0 | 0 | 기기 기준선 |
| 2 | 10 | 0 | **지금 방이 이미 겪고 있는 부담** |
| 3 | 10 | 3 | 우리가 새로 얹는 비용 (②와의 차이) |
| 4 | 10 | 8 | 한계. 여기서 멀쩡하면 N=5 |

### 통행

어슬렁거리는 공룡은 **캐릭터를 막지 않는다.** 지금 방 코드는 사람도 가구도 다 막게 돼 있어서
공룡이 문 앞에 서면 캐릭터가 못 지나간다. 겹치면 공룡이 옆으로 한 칸 비켜준다.
안 그러면 '귀엽다'가 '짜증난다'로 바뀐다.

## 만들지 않는 것 (YAGNI)

- 배고픔·애정 게이지, 방치 페널티 — 대표가 '가볍게'로 결정
- 펫끼리 상호작용 — 동시 1마리라 성립하지 않는다
- 손님이 남의 펫에게 밥 주기 — 실시간 DB가 필요해진다. 구경만
- 펫 성장·진화 — 나중에 얹을 수 있게 데이터만 열어 두고 이번엔 안 만든다
- 펫 도감 — 보관함으로 충분하다

## 단계

`index.html` 은 단일 파일이라 다른 창과 부딪힌다. **그 파일을 안 건드리는 것부터 한다.**

1. **측정 도구** — `dino-perf.html`, 둥가둥가 시트 추출. **완료(`a67c34c`)**
2. **에셋 파이프라인** — `char/pets/` 시트 정리, 소품 자르기, 공룡 4방향 정렬 스크립트.
   `index.html` 안 건드림
3. **데이터·카탈로그·렌더** — 펫 종류 신설, 구매, 방에 그리기
4. **행동 엔진** — 일과표, 종별 차이, 가구 올라가기
5. **UX** — 링 메뉴, 밥 주기, 공룡 펫 승격

각 단계 끝에 푸시하고 대표가 실앱에서 확인한다.

## 검증

- 일과표는 **순수 함수**다(입력: uid·펫id·시각). 노드에서 24시간을 훑어
  수면 시간 합계·덩어리 수가 종별 범위에 드는지 확인할 수 있다. 실기기 없이 검증되는 유일한 부분이다
- 나머지(크기·속도·자연스러움)는 **대표가 실앱에서 본다.** 내 로컬 미리보기로 판단하지 않는다
- 배포 전 필수 3종: `<script>` 6블록 `node --check` / `_SW_V` ↔ `sw.js` 숫자 일치 / 푸시 후 실앱 확인
