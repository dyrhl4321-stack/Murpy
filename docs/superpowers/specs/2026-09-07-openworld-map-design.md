# 머피월드 오픈월드 맵 설계 + 생성 워크플로우 (2026-09-07)

대표 지시(9-07): "애초에 설계를 디테일하게 잡고 워크플로우를 만들고 생성해야 버그 안 난다."
이 문서가 그 설계다. 맵을 추가·교체할 때는 **여기 순서대로만** 한다. 코드는 `tools/openworld_build.py`.

## 1. 월드 구조 (허브 + 연결 맵)

```
                 [산책로 walk]  ← 강·계단·데크 (순이 할매)
                     ↑ 윗길 (park 46~47열, 6~8행)
[광장 park] ─────────┤
 관리인 박씨·민준이   ↓ 가운데 길 (park 46~47열, 22~24행)
 분수·연못·놀이터    [야외 헬스장 outgym] ← 고무바닥·기구 (강 코치 + 운동 엑스트라 3)
```

- 광장이 허브. 출구는 **전부 그림 속 길이 오른쪽 가장자리 나무 틈으로 빠지는 자리**에만 둔다.
  포탈을 숨기거나, 길이 없는 곳에 링만 두는 것 금지(대표: "뜬금없는 곳에 포탈").
- 연결 맵은 **왼쪽 가장자리 입구 하나**(y≈45~53%)로 들어오고, 나머지 세 변은 나무·물로 닫는다.
  → "잘라 넣은 것처럼" 보이는 원인 = 길·데크가 화면 밖으로 잘려 나가는 것. 프롬프트에 CRITICAL FRAMING 으로 못박는다.
- 다음 후보: 놀이터 맵(민준이 이동), 강변 러닝 트랙. 같은 규칙.

## 2. 맵 규격

| 항목 | 값 |
|---|---|
| 캔버스 | 2048×2048, 48×48 타일(1타일 42.67px) |
| 저장 | 256색 팔레트 PNG(`Image.quantize FASTOCTREE, dither 없음`) ≈ 1.1MB. 원본(work/*.png)은 보관 |
| 생성 모델 | `gemini-3-pro-image-preview` `--size 2K`, `--ref` = 광장 원본(768px 축소본)으로 화풍 고정 |
| 입구 | 왼쪽 가장자리 길, 행은 그림에서 **실측**(`edge_road_rows`) — 손으로 적지 않는다 |
| 게이트 | `_FIELD_GATES` — 광장 출구는 46~47열, 도착은 상대 맵 (2, 입구 중앙행). 되돌아올 땐 (44, 출구 중앙행) |
| 충돌맵 | 바닥색(잔디·길·모래·고무·데크) 유사도 → 칸의 62% 이상이 바닥이면 개방, 물 20% 이상이면 차단. 입구·계단은 강제 개방 |
| NPC | `_MW_NPCS[].field`, `x/y` = 캔버스 %, 발끝 기준. 엑스트라도 `field` |
| 비둘기 | `_mwPigeons(n)` 공원 5 · 산책로 3 · 헬스장 2 |

## 3. 프롬프트 원칙 (맵)

1. 첫 줄에 "EXACTLY the same art style, palette, camera, tile scale, outline as the reference".
2. **CRITICAL FRAMING RULES** 블록: 어느 변이 닫히는지, 입구가 어느 변 몇 % 인지, "must NOT look cropped".
3. 안에 들어갈 오브젝트 목록은 **완결된 물건**으로(데크는 "완전히 맵 안에서 끝난다").
4. 캐릭터·글자·UI 금지.
5. 엑스트라가 설 자리를 위해 **빈 바닥 영역**을 요구한다(헬스장: "rubber floor with open space in the middle").

## 4. 엑스트라·NPC 애니 원칙

- 엑스트라는 **기구를 포함한 스프라이트**(풀업 바·벤치+바벨) 4프레임 strip. 맵에 그려진 기구 위에 겹쳐 놓지 않는다
  (대표: "철봉이 움직이는 것처럼", "벤치가 이두컬처럼" = 맵 기구와 스프라이트 동작이 안 맞은 것).
- 렌더는 안쪽 `.fr` strip 을 `translateX(-100%) steps(N)` 로. `background-position %` 금지(프레임 뒤섞임).
- 가로세로비가 141:224 가 아니면 `ar` 필드로 지정.
- 포즈 전환은 느리게 + 숨쉬기(npcBreathe). "깜박깜박" 금지.

## 5. 물 애니

`tools/water_anim.py fount|pond` — 맵 원본에서 물 픽셀만 위상(phase)으로 흘린 **24프레임 완벽 루프**.
제미나이로 프레임을 따로 뽑으면 프레임끼리 이어지지 않아 "끊겼다 생겼다" 한다(9-07). 물 박스는 `water_boxes.json`(색으로 실측).

## 6. 워크플로우 (맵 하나 추가/교체)

1. 프롬프트 작성(§3) → `tools/gen_asset.py --model gemini-3-pro-image-preview --size 2K --ref <광장 축소본>` → `char/fields/work/<map>_vN.png`
2. 눈검수: 네 변이 규칙대로 닫혔나, 입구 하나인가, 잘린 물건 없나. 아니면 **처음부터 다시**(부분 타일링 금지 — 잘라 붙인 티 난다)
3. `python tools/openworld_build.py` → 양자화 저장·충돌맵·입구 실측·게이트·NPC·물 박스·CSS 갱신, scratchpad 에 오버레이 3장
4. 오버레이 확인: 길·잔디 개방 / 나무·물·화단·벤치 차단 / 출구 칸 개방. 틀리면 샘플 좌표(잔디·길)만 고쳐 재실행
   — 샘플에 가장자리 나무를 찍으면 나무가 전부 열린다(9-07 실수). 길 색은 점이 아니라 베이지 중앙값
5. `python tools/water_anim.py fount && pond`
6. `node tools/all-scripts-syntax-check.mjs` + `module-syntax-check.mjs` → 커밋(원본·양자화본·시트·json 모두 add — `.raw.png` 는 gitignore 라 add 에 섞이면 통째로 실패한다)
7. `git pull --rebase` → `bump-version.mjs` → `check_version.py` → push → `scratchpad/pw/check.js`(fields 목록·PAGEERRORS)
8. 검수 폴더(`Desktop/머피브랜딩/…/에셋검수/날짜_오픈월드`)에 맵·시트·읽어주세요.txt

## 6-1. 9-08 추가 규칙
- 광장 출구: **왼쪽 가운데 → 야외 헬스장**, 오른쪽 위 → 산책로. 연결 맵의 입구는 광장 출구와 **마주보는 변**에(헬스장은 mirror 로 입구를 오른쪽에).
- `_FIELDS.<k>.sniff`(강아지 킁킁 스팟)·`_FIELDS.park.duck`(오리 물칸)은 빌드 스크립트가 색으로 실측해 박는다 — 손으로 적지 않는다.
- NPC 시트를 Pro 에 레퍼런스로 주면 **3×4 시트 형식이 따라온다**(strip 을 시켜도). 소품(벤치)은 맵 속 소품 크롭을 레퍼런스로 따로 뽑아 합성한다.
- 절차적 프레임(픽셀을 옮겨 만든 8f)은 몸을 도려낸다(민준이 사고) → 동작 프레임은 항상 Pro 4f.
