# 얼굴 커마권 시스템 설계

2026-09-04 · feat/face-custom · 대표 승인 완료

친구초대 이벤트는 **별도 스펙**이다. 이 문서는 커마권만 다룬다 —
초대의 보상이 커마권이므로 이쪽이 먼저 돌아야 한다.

## 1. 무엇을 만드는가

유저가 자기 얼굴로 픽셀 캐릭터를 만들어 머피월드에서 쓰는 기능.

| 항목 | 결정 |
|---|---|
| 획득 | 상점에서 1,000머피로 구매 + 베타 무료권 지급 (둘 다) |
| 지급 | 생성 즉시 지급. 관리자 승인 큐 없음 |
| 재생성 | 무료 2회 (커마권 1장 = 최대 3장 생성, 실비 약 600원) |
| 생성 위치 | Firebase Functions (서버). 제미나이 키는 Secret Manager |
| 보유 | 여러 개. 각각 유저가 이름을 붙인다 |
| 도용 방지 | 얼굴인증 통과자만 + 인증에 쓴 프로필 얼굴과 동일 인물만 |

정식 가격(19,900원 실결제 vs 1,000머피)은 PG 시점에 정한다. **상수로 분리**해
한 곳만 고치면 되게 한다.

## 2. 왜 몸통을 데이터로 빼야 하는가

지금 `window._CHAR_BODIES`(index.html 3777행)는 하드코딩이다. 고객이 한 명 생길
때마다 사람이 index.html 을 고치고 앱을 새로 배포해야 한다. **"바로 지급"이
원천적으로 불가능**하다. 이 스펙의 절반은 이 구조를 푸는 일이다.

### 데이터 구조

```
users/{uid}
  faceTickets: number            보유 커마권 장수
  characterSheet: string|null    ★현재 착용 중인 커마 시트 URL (남이 나를 그릴 때 씀)
  character.body: 'face:{charId}' 착용 중인 몸통 (기존 필드 재사용)

users/{uid}/faceChars/{charId}
  name: string                   유저가 붙인 이름 (1~12자)
  sheetUrl: string               Storage 시트 URL (423x896)
  skinUrls: { t1,t2,t4,t5,t6 }   피부톤 5종 URL
  eyes: { y: number, x: [l, r] } 무궁화 하트눈 좌표 (서버가 실측)
  retryCount: number             재생성 횟수 (서버가 강제, 상한 2)
  createdAt, updatedAt
```

`characterSheet` 가 핵심이다. 오버월드·피드·채팅에서 **남의** 커마 캐릭터를
그릴 때 서브컬렉션까지 읽으러 가면 느리다. 착용 시점에 URL 하나를 유저 문서에
복사해두면 기존 렌더 경로가 그대로 돈다.

### 런타임 주입

앱 부팅 시 내 `faceChars` 를 읽어 `_CHAR_BODIES` 에 주입한다:

```js
_CHAR_BODIES['face:' + charId] = {
  name, src: sheetUrl, skinBase: null, skinUrls,
  cw: 141, ch: 224, wearable: true, fixedHair: true, kin: 'human',
  tag: '커마', ownerUid: uid, dynamic: true
};
SQ_MG_EYES['face:' + charId] = eyes;
```

`kin:'human'` 이라 기존 human 옷을 그대로 입는다. 로스터·착용·옷 호환 코드는
**한 줄도 안 고친다**.

## 3. 도용 방지

### 원칙: 파일 업로드 경로를 만들지 않는다

파일을 고를 수 있으면 남의 사진이 들어올 길이 열린다. 커마 신청 화면은
**그 자리에서 웹캠으로만** 찍는다.

### 기존 인증 엔진 재사용

현행 `captureFaceVerify()`(23843행)는 프로필 사진에서 기준 디스크립터를 뽑고
(`findRefDescriptor`) 웹캠 프레임과 `faceapi.euclideanDistance < 0.55` 로 비교한다.
통과하면 `users/{uid}.faceVerified=true` 만 저장하고 **사진은 버린다**.

커마 생성도 같은 비교를 통과한 프레임만 입력으로 쓴다. 인증에 쓴 그 얼굴과
같은 얼굴이라는 게 자동으로 보장된다. 별도의 "인증 사진 저장"이 필요 없다.

### 구멍과 대응

| 구멍 | 대응 |
|---|---|
| 남의 사진으로 생성 | 파일 업로드 없음. 웹캠 캡처 + 프로필 대조 통과분만 |
| 앱을 우회해 서버 직접 호출 | Functions 에서 Firebase Auth 검증 + App Check. 클라가 보낸 "통과했음"을 믿지 않고 **서버가 티켓과 faceVerified 를 다시 확인** |
| 티켓 없이 생성 / 이중 차감 | 티켓 차감을 Firestore 트랜잭션으로. 동시 요청에도 한 장만 나간다 |
| 생성 실패인데 티켓만 소모 | 선차감 후 실패 시 같은 트랜잭션으로 환불 |
| 재생성 무한 = 비용 폭주 | `retryCount` 상한을 **서버가** 강제. 유저당 일일 생성 상한도 서버에 |
| 제미나이 키 유출 | Secret Manager. 클라이언트로 절대 안 내려간다 |
| 프롬프트·민머리 시트 유출 | 공개 저장소 금지 유지. 비공개 Storage 또는 서버 환경변수 |
| 얼굴인증 자체를 남의 사진으로 뚫기 | 기존 인증의 위협모델이지 커마권이 새로 여는 구멍이 아니다. 신고 기능으로 사후 대응 |

## 4. 사용자 흐름

```
로스터 "내 얼굴로 만들기"
  ├ 티켓 0장      → 상점으로
  ├ 얼굴인증 없음  → 인증 흐름으로      ← 프로필이 여기서 채워진다
  ├ 프로필 사진 없음 → 사진 등록으로     ← 인증의 선행 조건
  └ 통과
      ↓
   웹캠 캡처 (프로필 대조 통과 프레임 확보)
      ↓
   서버: 티켓 차감 → 제미나이 Pro 2K → 칸 단위 규격화(face_grid)
        → 눈 좌표 실측 → 피부톤 5종 굽기 → Storage 업로드 → faceChars 문서
      ↓
   결과 미리보기
      ├ "이 캐릭터 쓸래요" → 이름 입력 → 저장 → 로스터에 추가 → 착용
      └ "다시 만들기" (남은 횟수 표시) → 재생성
```

생성은 30~60초 걸린다. 대기 화면에 진행 표시가 필요하다.

## 5. 연결 지점 — 빠뜨리면 버그가 나는 곳

커마 몸통이 등장해야 하는 모든 경로:

| 곳 | 처리 |
|---|---|
| 로스터 `mwRenderRoster` | 런타임 주입된 몸통이 자동으로 뜬다 |
| 소유 판정 `_charBodyIsMine` | 2026-09-04 에 한 곳으로 모았다. 동적 몸통은 `ownerUid` 로 판정 |
| 착용·옷 호환 `charPickBody`/`_charFits` | `kin:'human'` 이라 기존 옷 그대로 |
| 저장 `_charPersistCharacter` | `character.body = 'face:{charId}'` + `characterSheet` 동시 갱신 |
| 오버월드·피드·채팅·프로필 카드 | `characterSheet` URL 하나로 해결 |
| 머피캠 필터 | 같은 경로 |
| **무궁화 하트눈 `SQ_MG_EYES`** | 서버가 눈 좌표를 실측해 저장. 없으면 human 좌표가 쓰여 하트가 어긋난다 |
| 피부톤 선택 | 동적 몸통은 `skinBase` 대신 `skinUrls` 를 본다 — 분기 필요 |

## 6. 예상 버그와 방어

| 위험 | 방어 |
|---|---|
| 시트 URL 이 죽어 캐릭터가 안 보임 | 로드 실패 시 base(human)로 폴백하고 조용히 넘어간다. 빈 화면 금지 |
| 남의 캐릭터를 그릴 때 `characterSheet` 가 없음(구버전 유저) | 없으면 기존 하드코딩 몸통으로 폴백 |
| 착용 중인 캐릭터를 삭제 | 삭제 시 자동으로 base 몸통으로 되돌린다 |
| 이름에 욕설·긴 문자열 | 1~12자 제한 + 기존 닉네임 금칙어 필터 재사용 |
| 생성 중 앱을 닫음 | 서버가 완료하면 문서가 생기므로 다음 접속 때 "새 캐릭터가 도착했어요"로 회수 |
| 웹캠 권한 거부 | 거부 사유를 안내하고 티켓은 **차감하지 않는다** |
| face-api.js CDN 로드 실패 | 인증 흐름과 동일하게 실패 처리. 티켓 차감 없음 |
| 동적 몸통 키 충돌 | `'face:'` 접두사를 강제해 기존 키와 절대 안 겹치게 |

## 7. 이탈 지점과 완화

| 이탈 지점 | 완화 |
|---|---|
| 프로필 사진이 없어 인증을 못 함 | 커마 진입에서 사진 등록을 **그 자리에서** 시킨다. 다른 화면으로 던지지 않는다 |
| 웹캠이 부담스러움 | "사진은 저장되지 않습니다"를 명시. 실제로 저장 안 한다 |
| 30~60초 대기 | 진행 표시 + 완성 예고. 앱을 닫아도 완성되면 받는다고 안내 |
| 결과가 마음에 안 듦 | 재생성 2회 무료. 남은 횟수를 미리 보여준다 |
| 1,000머피가 비싸 보임 | 광고 팝업에 실물(재진·패수현)을 보여줘 가치를 먼저 납득시킨다 |
| 만들고 안 씀 | 만든 즉시 착용 + 오버월드로 이동해 내 캐릭터가 서 있는 걸 보여준다 |

## 8. 광고 팝업

기존 머피월드 홍보 팝업(`#mw-promo`, `showMwPromo`, 15886행) 패턴을 복제한다.

- 히어로: `_charMiniHTML('jaejin', 96)` + `_charMiniHTML('paesuhyun', 96)` 나란히
- CTA: "내 얼굴로 만들기" → 로스터의 커마 진입
- 트리거: 기존과 동일(탭 3번 이상·세션당 1회·최대 3회) + **이미 커마 캐릭터가 있으면 안 뜬다**

## 9. 무료권 차등 지급 (베타)

근방단 카톡 합의(2026-09-04):
- 조건 = 스쿼드 1회 참여 이상 + 외부 친구초대
- 스쿼드 참여 횟수 차등(채은) / 친구초대 n명 차등(지원)

베타 기간은 **커마권을 직접 지급**한다(대표가 "1,000머피 상당 커마권 무료"로
약속했으므로). 정식 전환 때 머피 지급으로 통일해 경제를 하나로 모은다.

초대 자동 집계는 친구초대 스펙에서 다룬다. 그 전까지는 관리자 수동 지급.
