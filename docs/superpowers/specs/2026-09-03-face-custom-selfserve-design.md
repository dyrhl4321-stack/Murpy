# 얼굴 커스터마이징 자가생성 (Phase A) 설계

2026-09-03 · 대표 승인(브레인스토밍 "ㄱㄱ") · 병렬 워크플로우: 이 창 담당(인앱+Function), 파이프라인 로직은 f5 세션 인수인계.

## 0. 목표와 범위

**한 문장**: 근방단 베타테스터가 앱에서 셀카를 올리면 서버가 자동으로 "내 얼굴 도트 캐릭터"를 만들어, 이름을 붙여 내 캐릭터로 저장한다.

**왜 자가생성인가 (대표 확정)**: 이게 나중에 파는 상품의 핵심 흐름이다. 사람이 손보정하는 반자동은 "판매"가 안 된다. 베타는 **자동 생성의 품질**을 실사용자로 검증하는 것 — 결과가 거칠 수 있음(손보정 단계 없음)을 대표도 수용("이상할 수 있다").

**이 스펙의 범위 = Phase A (자가생성 본체)**. 친구초대 이벤트는 **Phase B 별도 스펙**으로 분리(독립 서브시스템). Phase A 없이 B 없다.

**비범위**: 친구초대(ref 링크·보상), PG 실결제 연동(베타는 무료), 판매용 커마권 경제 확정.

## 1. 사용자 흐름 (인앱)

1. **진입점**: 머피월드 꾸미기 탭 캐릭터 섹션에 **"내 얼굴로 만들기 (베타)"** 슬롯/버튼.
   - 노출 조건 = 베타 대상(§4) **그리고** `faceVerified === true`. 아니면 슬롯 자체가 안 보이거나 "근방단 활동 멤버 베타"·"본인 얼굴 인증 먼저" 안내.
   - 안내 문구: "베타 · 결과가 이상할 수 있어요" + "근방단 스쿼드 활동 멤버에게 1,000머피(19,900원) 상당 얼굴 커마권 무료 지급".
2. **셀카 업로드**: 정면 셀카 몇 장(가이드 권장 6장 근처, 최소 N장 — §7). 기존 Storage 업로드 경로(`uploads/{uid}/`) 재사용. 본인 얼굴 인증된 계정만이라 타인 얼굴 사용 방지.
3. **생성 중**: "만드는 중…"(1~2분). 서버 Function 이 §3 파이프라인 수행. 진행 상태는 Firestore 문서(`faceJobs/{uid}` 또는 users.faceCustom.status)로 폴링/구독.
4. **미리보기 → 이름 + 톤 선택**: 완성 시트 미리보기 → **이름 정하기**(예: "현수 얼굴") + 피부톤(t1~t6) 선택 → **적용**.
5. **적용**: 내 캐릭터 몸통이 커스텀 얼굴로 바뀐다(데이터 기반 몸통, §5). 언제든 기본 몸통으로 되돌리기 가능.

## 2. 컴포넌트 분해

| 컴포넌트 | 책임 | 위치 |
|---|---|---|
| 진입점 UI | 베타·인증 게이팅, 슬롯 노출, 안내 | index.html 꾸미기 캐릭터 섹션 |
| 셀카 업로드 UI | 셀카 N장 선택·업로드·잡 생성 | index.html |
| 생성 Function | 셀카→제미나이→규격화→graft→톤5종→Storage→메타 | functions/ (Python 2nd-gen) |
| 잡 상태 | 진행/완료/실패 상태 전달 | Firestore `faceJobs/{uid}` |
| 커스텀 몸통 로더 | users.faceCustom 메타로 _CHAR_BODIES 동적 등록 | index.html (_charRenderTo 경로 유지) |

| 경제/상한 | 무료 지급·재생성 상한·가격 상수 | index.html + Function |

## 3. 서버 생성 파이프라인 (핵심·제일 큼)

`tools/face_pipeline.py`(f5 세션 작성, 오프라인 검증됨)의 로직을 **Firebase Python Functions**로 포팅:
1. 제미나이(나노바나나)로 12칸 워크 시트 생성 — **비밀 프롬프트**(민머리 베이스 시트 + 셀카 + 고정 지시문). 가이드 1단계 원문 사용.
2. 규격 정렬 423×896(셀 141×224, 3×4) — flood 배경 제거·NEAREST·알파 이진화.
3. `face_graft` — base 몸통(char/walk.png) + AI 머리만 이식(목 아래 base 원본). 셀별 컷라인 실측(가이드 원칙).
4. `skin_bake` — 피부톤 t1~t6 5종 굽기(base 주황 피부 기준).
5. 산출물(시트 + 톤 5장)을 **비공개 Storage**에 저장, 메타를 Firestore 에 기록.

**로직 정확성**: `tools/face_graft.py`·`skin_bake.py`·가이드가 정답 구현. 포팅 시 그 로직 그대로 옮긴다. 완성 후 **재진 재현 테스트**(jaejin_src → graft 결과 0px diff, 톤 5종 diff 0)로 검증 — f5 세션이 오프라인에서 쓴 검증 방식 그대로.

**자동화 견적**: 제미나이 호출 3회 안팎 ≈ $0.12/건. 손보정 단계는 자동에 없음(베타 품질 거칢은 의도).

## 4. 베타 게이팅

- **대상 = 근방단 스쿼드 "출석 활동" 멤버** — 단순 가입/멤버십이 아니라 출석 기록 기준(`squads` 멤버 데이터의 `checkedIn`/`part` 기록 **1회 이상**). ★정확한 문턱은 착수 직전 대표 재컨펌.
- **그리고 `faceVerified === true`**(본인 얼굴 인증). 어뷰징·타인 얼굴 방지의 핵심.
- 관리자(대표)는 항상 통과(실기기 확인용).
- 판정 함수 하나(`_faceBetaEligible(user)`)로 모아 UI·Function 양쪽이 같은 기준 사용.

## 5. 데이터 모델

- `users.faceCustom` = **메타만**: `{ name, sheet: <Storage경로/URL>, tones: {t1..t6: URL}, tone: 't2', eyes: {x:[..],y:..}, at, gen: <재생성 횟수> }`. ★users 문서는 전원이 읽으므로 큰 것 금지 — PNG 는 절대 안 넣는다.
- 시트·톤 PNG(6장) = **Storage**(`uploads/{uid}/face/*` 또는 전용 경로).
- **커스텀 몸통 = 데이터 기반**: 지금 jaejin 처럼 `_CHAR_BODIES` 하드코딩 대신, users.faceCustom 이 있으면 런타임에 커스텀 몸통 엔트리를 만들어 등록(`kin:'human'`, `fixedHair:true`, `wearable:true`, owner=본인).
  - ★렌더는 반드시 `_charRenderTo` 하나로만, 겹 순서는 `_charLayerOrder` 로만(사본 만들면 사고 — 메모리 규칙).
  - 커스텀 얼굴은 **주인 + 관리자에게만** 보인다(기존 jaejin 규칙 그대로).
- 무궁화꽃 `SQ_MG_EYES` — 커스텀 얼굴별 눈 좌표 필요. 없으면 human 폴백을 **명시적으로**(빈 값 방치 금지). 눈 좌표는 파이프라인이 산출하거나 human 기본값 사용.

## 6. 보안 (★functions/ 는 공개 저장소)

- **생성 프롬프트·민머리 베이스 시트·제미나이 키를 Functions 소스에 절대 넣지 않는다** — 어제 비공개로 옮긴 노하우가 도로 유출된다.
  - 프롬프트 → **Secret Manager**(또는 Functions 환경변수/설정).
  - 민머리 베이스 시트 → **비공개 Storage** 경로에서 런타임 로드.
  - 제미나이 키 → **Secret**.
  - 코드엔 **참조만**.
- 생성 원본(고객 셀카)·프롬프트·비공개 시트는 공개 저장소 커밋 금지(Murpy_private / 비공개 Storage).
- 셀카는 본인 인증 계정만(faceVerified). 부적절 이미지 필터(Vision SafeSearch)는 베타 후 검토(비용 $0.0015/건).

## 7. 경제 · 비용 방어

- **가격 상수 분리**: `FACE_TICKET_PRICE` 하나로. 정식 가격 모델(실결제 19,900원 vs 1,000머피 통합)은 **PG 시점까지 미확정** → 상수만 바꾸면 되게. 유저 표기 = "1,000머피(19,900원) 상당".
- **베타 = 무료 지급**. 코스메틱이라 경제 훼손·이탈 없음 → 넉넉히 뿌리는 게 의도된 정책(대표). 상한은 **비용 방어** 수준.
- **★재생성 상한(비용 방어 핵심)**: 자동 품질이 거칠어 재시도가 많을 것. 무료 재생성 **2~3회 상한**(users.faceCustom.gen 카운트). 초과 시 안내. 건당 실비 ~200원이 재시도마다 쌓이는 걸 막는다.
- **단가 분석(확인됨)**: 제미나이 ~$0.12 + 서버/스토리지 무시 ≈ **건당 ~150~200원**. 정식가 대비 마진 ~99%. 손해 아님.
- **정식 판매는 웹 결제 유도** — 구글 인앱결제(디지털 상품 15~30% 의무)를 피한다.

## 8. 에러 처리

- 생성 실패(제미나이 오류·타임아웃) → 잡 status='fail', 재생성 카운트 차감 안 함, "다시 시도" 안내.
- Function 타임아웃(제미나이 느림) → 비동기 잡 + 상태 폴링(동기 응답 대기 금지).
- 셀카 업로드 실패 → 기존 Storage 업로드 에러 처리 재사용.
- 커스텀 몸통 시트 로드 실패 → 기본 몸통 폴백(빡빡이 방지).

## 9. 테스트

- **재진 재현 테스트**(포팅 검증): graft 0px diff, 톤 5종 diff 0 — 파이프라인 로직이 오프라인과 동일함을 못박음.
- 게이팅 단위 테스트: `_faceBetaEligible` (출석 有/無 × faceVerified 有/無 × 관리자).
- 재생성 상한 단위 테스트: gen 카운트 경계.
- 데이터 기반 몸통 로더: users.faceCustom 있음/없음/깨진 메타 → _charRenderTo 폴백.

## 10. 단계 (Phase A 내부 순서)

1. 파이프라인 Function 포팅 + 재진 재현 검증 (백엔드 핵심).
2. 데이터 기반 커스텀 몸통 로더 + 적용/되돌리기 (렌더).
3. 진입점·업로드·결과 UI + 게이팅 + 재생성 상한.
4. 무궁화 눈 좌표·경제 상수·안내 문구.

## 11. 열린 확인(착수 직전 대표 컨펌)

- 베타 게이팅 출석 문턱(1회 이상? N회?).
- 셀카 최소 장수.
- 재생성 무료 상한(2 vs 3).
- 정식 가격 모델(PG 시점 — 스펙은 상수라 지금 안 막힘).
