# 명예의 전당 (랭킹) — 설계

작성 2026-08-19 · 대표 승인 완료(브레인스토밍 8-18 저녁)

## 1. 왜 만드는가

대표 원문:

> "결국 운동을 많이 하고 활동을 많이 하는 사람들이 많이 노출될 수 있는 환경이 되어 있음 좋겠음."
>
> "실시간 스쿼드 필드(챗 + 캐릭터 움직이는 거) 보고 일단 우와! 이러긴 하는데, 범프의 경우
> 스쿼드가 만들어지고 실제 만남이 이루어지기 전까지 이탈이 많아질 확률이 높다고 봄."

지금 앱에 **노력이 노출로 바뀌는 자리가 하나도 없다.** 매칭은 사진, 피드는 최신순,
스쿼드는 시간순이다. 열심히 한 사람이 눈에 띌 방법이 없다.

범프가 *오프라인* 아하 모먼트라면, 이건 **온라인에서 눈으로 보이는 아하 모먼트**다.

## 2. 대표가 확정한 것

| | 결정 |
|---|---|
| 자리 | **상단 헤더에 트로피 아이콘** — 어느 탭에서든 항상 보인다 |
| 구성 | 화면 하나 + **목록별 서브탭** (대표: "목록별로 탭만 나누면 되잖아") |
| 팝업 | **주 1회** — 헬토리 광고창 같은 전체화면 팝업 |
| 팝업 내용 | 현재 1위 + **1위가 남긴 한마디** |
| 인기 룸 점수 | 가구 수 가중치를 올린다 (대표: "가구를 많이 넣었다는 것 자체가 신경 쓴 것") |
| 제외 | 대표 본인 계정 2개 |

★ 인기 룸/캐릭터 점수와 계정 제외는 **이미 배포됨** (`c769f67`, `ef2b893`). 이 문서 범위 밖.

## 3. 데이터 — 새로 쌓을 것이 없다

랭킹에 필요한 숫자가 **이미 `users` 문서에 쌓이고 있다.** 시즌 한정 오브젝트 시스템이
7월에 깔아둔 카운터를 그대로 읽는다. 새 컬렉션 0 · 새 인덱스 0 · 보안규칙 변경 0.

| 랭킹 | 읽는 필드 | 쌓는 곳 |
|---|---|---|
| 인증왕 | `monthly.{YYYY-MM}.feed` | `mwBumpMonthly('feed')` — 인증글 작성 |
| 체크인왕 | `monthly.{YYYY-MM}.checkin` | `mwBumpMonthly('checkin')` — 센터 체크인 |
| 스쿼드장 | `hostStats.completed` | 스쿼드 완료 시 `increment(1)` |
| 스쿼드 참석왕 | `monthly.{YYYY-MM}.squad` | `mwBumpMonthly('squad')` — 출석 |

### 읽기 전략

`getDocs(collection(db,'users'))` **한 번**. `users` 는 `allow read: if true` 이고
앱이 이미 전체를 읽는 곳이 여러 군데다(매칭·홈 인기·리텐션 통계). 검증된 경로다.

- 홈 '지금 인기'(`loadHomeTrending`)도 같은 읽기를 한다 → **결과를 공유**해 읽기 횟수를 늘리지 않는다.
- 세션당 1회만 읽고 `window._hofCache = { at, rows }` 에 담는다. 10분 지나면 다시 읽는다.

### 달 키는 실제 달을 쓴다 (★함정)

`mwSeasonKey()` 는 **인자 없이 부르면 관리자 시즌 실험실(`_seasonLab`) 오버라이드를 탄다.**
랭킹이 그걸 타면 대표가 시즌을 실험하는 동안 전 유저의 랭킹 기준 달이 같이 바뀐다.

```js
const HOF_MONTH = () => window.mwSeasonKey(new Date());   // 인자를 준다 = 실험실 무시
```

### 제외 대상

- 임시(익명) 계정
- `deleted: true` (탈퇴)
- 대표 계정 2개 — `3ojRNNyRutYE4IDQn2GrJDcXz0Q2`(패수현) · `h0I8ms36owTByTACh6gSw3sgCrf1`(김현수)
  ※ 홈 인기 카드와 **같은 상수를 쓴다.** 두 벌이 되면 한쪽만 고치는 사고가 난다.
- 해당 항목이 0인 사람 (0회를 줄 세우면 목록이 0으로 가득 찬다)

### 동점 처리

닉네임 가나다순. 무작위로 두면 **볼 때마다 순서가 바뀌어** 등수가 신뢰를 잃는다.

## 4. 화면 셋

### A. 명예의 전당 패널 (`#hof-panel`)

기존 `.panel` / `.panel-header` / `.panel-body` 문법. 서브탭은 기존 `.tab-bar` / `.tab-btn` 재사용.
**새 UI 문법을 만들지 않는다.**

```
┌ 명예의 전당 ─────────────────────┐
│ [인증] [체크인] [스쿼드장] [참가]  │
├──────────────────────────────────┤
│  1  근손실방지단장          42회   │
│  2  마조리카                38회   │
│  3  ...                            │
│  ─────────────────────────────    │
│  7  나                      12회   │  ← 항상 맨 아래 고정
└──────────────────────────────────┘
```

- 상위 **10명** + **내 순위는 10위 밖이어도 맨 아래 고정**
  → 내 등수가 보여야 "한 칸만 올리면 되는데"가 생긴다. 이게 돌아올 이유다.
- 줄을 누르면 그 사람 프로필(`openUserProfile`)
- 등수는 **색이 아니라 숫자 크기·굵기**로 구분한다. 메달 이모지 금지.
  ★`골드(#F5C24B)` 는 앱 규칙상 **별점·코인 전용**이다([[feedback_murpy_color_system]]).
  1위에만 골드를 허용할지는 **대표 판단** — 기본은 안 쓰는 쪽으로 만든다.
- 아직 아무도 없으면 "이번 달은 아직 비어 있어요 · 첫 주인공이 되어보세요"

### B. 홈 한 줄

`#home-live-bar` **바로 아래**. 카드가 아니라 한 줄이라 자리를 안 먹는다.

```
이번 달 인증 1위 근손실방지단장 · 내 순위 7위  ›
```

- 로그인 안 했으면 내 순위 부분을 빼고 1위만
- 누르면 명예의 전당 패널

### C. 스쿼드 탭 '인기 스쿼드' 섹션

'오픈한 스쿼드' 목록 **위**. `squads` 에서 참가자(`memberUids.length`) 많은 순 3개.

★ 명예의 전당에 **넣지 않는다.** 나머지 넷은 *사람*이고 목적이 **자랑**인데, 이건 *스쿼드*고
목적이 **참가**다. 눌렀을 때 갈 곳이 다르다(프로필 vs 스쿼드 상세).

나중에 정기반이 다시 열리면 자연스럽게 여기 올라온다 — 대표가 말한
"인기 정규반을 스쿼드 탭 안에 랭킹식으로"가 이 자리다.

## 5. 헤더 트로피

```
하트 · 톡 · 종 · [트로피] · 프로필
```

- `.header-icons` 간격 **`16px → 12px`**. 실측: 360px 폰(갤럭시)에서 5개가 1px 넘쳐서,
  간격을 4px 줄이면 16px 여유가 생긴다.
- **배지를 안 단다.** 하트·톡·종은 "나한테 뭔 일이 생겼다"라 배지가 의미 있지만
  트로피는 "내가 보러 가는 곳"이다. 여기까지 빨간 점을 달면 진짜 신호 셋의 무게가 떨어진다.
- 아이콘은 나머지와 같은 값 — `stroke-width:1.8`, `opacity:0.7`, 20×20. 머피 라인 SVG(이모지 금지).

## 6. 주간 팝업

헬토리 홍보 팝업(`#mw-promo` / `showMwPromo` / `_maybeMwPromo`)과 **같은 문법**.
전체화면 모달 + `show` 클래스 + localStorage 게이트 + `다시 보지 않기`.

### 언제

**월요일 첫 접속에 1회.**

주차는 **그 달의 몇 번째 주**로 센다(ISO 주차가 아니다 — 종목 회전이 달 단위 카운터와
같은 주기를 돌아야 한다).

```js
const hofWeek = (d) => Math.min(4, Math.floor((d.getDate() - 1) / 7) + 1);  // 1~4
const hofWeekKey = (d) => window.mwSeasonKey(d) + '-W' + hofWeek(d);        // "2026-08-W3"
```

`localStorage.hof_popup_week` 에 이 키를 적어 같은 주에 두 번 뜨지 않게 한다.
5주차(29~31일)는 4주차로 접어 넣는다 — 종목이 넷이라 다섯 번째 칸이 없다.

### 주차마다 종목을 돌린다 (★중요)

카운터가 **월 누적**이라 월초에 앞서 나간 사람이 그 달 내내 1위다.
같은 얼굴이 4주 연속 뜨면 첫 주만 재밌고 그다음은 광고가 된다.

| 그 달의 주차 | 주제 |
|---|---|
| 1 | 인증왕 |
| 2 | 체크인왕 |
| 3 | 스쿼드장 |
| 4 | 스쿼드 참석왕 (29~31일도 여기) |

→ **네 명이 돌아가며 주인공**이 된다. 노출이 분산되고 "나는 체크인으로 승부 봐야지"가 생긴다.
새 데이터가 필요 없다.

### 내용

1위 캐릭터(`mwMiniCharHtml`) + 닉네임 + 기록 + 한마디.
버튼 = `명예의 전당 보기` / `닫기`. 하단에 `다시 보지 않기`.

## 7. 1위 한마디 (`users.hofMsg`)

- 쓰는 자리 = **명예의 전당에서 내가 1위일 때만** 입력칸이 뜬다
- **30자 제한.** 방 상태메시지(`roomMsg`)와 같은 문법 — 새로 만들 것이 없다
- 표시는 `textContent` (주입 안전)

### 모더레이션 (필수)

이건 **전체 유저에게 팝업으로 나가는 유일한 자유 텍스트**다. 대숲 글보다 노출이 세다.

- 신고·차단은 이미 있다(`blockUser` / `openPostMenu`) — 거기에 붙인다
- **관리자가 지우는 경로**를 같이 만든다. 관리자는 남의 `users` 문서를 쓸 수 있다
  (`firestore.rules`: `allow write: if isOwner(userId) || isAdmin()`)
- 차단한 사람이 1위면 팝업에 한마디를 **안 보여준다**(이름·기록만)

## 8. 안 하는 것 (YAGNI)

주간 카운터 신설 / 지난달 아카이브 / 랭킹 보상 머피 / 랭킹 푸시 알림 /
프로필에 등수 표시 / 인기 스쿼드를 명예의 전당에 넣기.

→ **랭킹이 실제로 사람을 움직이는지 먼저 보고** 정한다.

## 9. 위험 · 한계

### (1) 전체 users 읽기는 영원하지 않다

지금 46명이라 한 번에 읽어도 무시할 수준이다. **500명쯤부터 무거워진다.**
그때는 상위 20명만 담은 집계 문서(`stats/hof`)로 바꾼다. 코드에 전환 지점을 주석으로 박는다.

### (2) ★공정성 하드룰과의 경계

랭킹 상위 노출은 *활동으로 번 것*이라 하드룰 위반이 아니다.
다만 **매칭 덱 순서에는 절대 반영하지 않는다.** 랭킹이 매칭 우선순위를 건드리는 순간
"시간 많은 사람이 매칭도 유리한" 구조가 되고 그건 하드룰 위반이다.

### (3) 닉네임 중복

앱에 **닉네임 중복 검사가 없다**(온보딩은 `maxlength=10` 만 본다).
랭킹은 사람을 이름으로 보여주는 화면이라 중복이 있으면 바로 티가 난다.
이 문서 범위 밖이지만 **가까운 시점에 신규 가입만 막는 검사**를 넣어야 한다.

### (4) 스쿼드장 랭킹은 누적이다

`hostStats.completed` 는 월 구분이 없다. 즉 **한 번 1등하면 계속 1등**이다.
지금은 그대로 간다(초기엔 오히려 '개척자'가 보이는 게 낫다). 사람이 늘어 고이면
`monthly.{월}.squadHost` 를 새로 쌓는다 — 그때 결정한다.

## 10. 구현 순서

1. 데이터 계층 — `window.loadHof()` : users 1회 읽기 → 4종 랭킹 계산 + 캐시
2. 명예의 전당 패널 (서브탭 4종 + 내 순위 고정)
3. 헤더 트로피 + 간격 조정
4. 홈 한 줄
5. 스쿼드 탭 인기 스쿼드 섹션
6. 1위 한마디 (입력 + 관리자 삭제)
7. 주간 팝업 (주차 로테이션)

1~3 이 되면 **눈에 보이는 것이 나온다.** 4~7 은 그 위에 얹는다.
