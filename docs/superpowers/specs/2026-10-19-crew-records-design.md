## 1. 왜

대학 러닝 동아리를 머피로 데려온다(대표: "어린 친구들이 많이 썼으면"). 러너는 스트라바·나이키 공유 카드를
보여 주는 걸 좋아한다. 머피는 그 카드를 받아 "진짜인지 확인"하고(네이버 영수증 리뷰 느낌), 인증된 기록만
크루 점수로 쌓는다. 유치 혜택은 무료 PT(시작 2회 + 크루 목표 달성 시 3회) — 오프라인 운영, 앱은 달성 여부만 보여준다.
헬스 쪽은 이미 있는 헬스장 GPS 체크인으로 바로 크루 출석을 쌓는다.

## 2. 목표 / 비목표 / 반목표

목표(1차 = 웹만, 앱 심사 없음)
1. **크루**: 관리자가 만든 크루에 초대 링크로 가입. 여러 크루 동시 가입 가능. 탈퇴해도 그 크루에 쌓인 기록은 남는다.
2. **러닝 인증샷 올리기**: 스트라바·나이키 공유 카드 캡처를 올리면 서버가 거리·시간·페이스·날짜를 읽고,
   "스캔" 연출 뒤 결과를 보여준다. 1차에서는 원본(건강 앱) 대조가 없으므로 전부 **미인증**으로 저장된다.
   카드는 판정과 상관없이 개인 기록·크루 피드에 그대로 보인다.
3. **개인 기록**: 누적 거리, 이번 달 거리, 인증 횟수, 최고 기록(가장 긴 거리·가장 빠른 페이스), 연속 주.
4. **크루 페이지**: 누적·이번 달 거리/출석, 이번 주 참여 인원/전체, 크루 안 이번 달 순위, 최근 인증 카드 피드,
   진행 중 챌린지 막대, 지난 챌린지 결과, 마일스톤(누적 100·500·1,000km) 칭호.
5. **헬스 출석 누적**: 기존 체크인(checkins 문서 생성)이 소속 크루의 출석으로 하루 1회 쌓인다.
6. **헬스장 성주**: 그 헬스장 이번 달 체크인 1위를 체크인 화면에 표시.
7. **크루 목표 챌린지**: 관리자가 만든다. 러닝 2주 1인 15km×인원 / 헬스 2주 1인 출석 6회×인원. 인증된 기록만 합산.
   달성 시 멤버 전원 머피 + "PT 3회 추가" 안내 + 관리자 알림.

비목표(이번엔 안 함)
- 건강 앱(HealthKit)·헬스 커넥트 대조 → 2차(아이폰 1.1.0) / 3차(안드로이드). 1차는 그 자리를 비워 두되
  서버 판정 함수가 원본 기록을 받을 수 있는 모양으로 만든다.
- 공유 버튼 → 머피 바로 보내기(공유 확장) → 아이폰 1.1.0.
- 1:1 크루 대결 → 1차-b(1차 배포 직후). 이번 설계에 데이터 모양만 정한다.
- 헬스 영상 인증·3대 클럽 → 4차. 시즌 리그·공성전 → 나중.
- 스트라바 계정 연결(OAuth) — 약관상 크루 합산 불가로 제외(대표 확정).
- 크루 마일스톤 "한정 아이템" — 에셋이 없다. 1차는 칭호만, 아이템은 에셋 확정 뒤.

반목표(이러면 실패)
- 사진만 보고 "인증됨"을 준다 — 금지. 인증됨은 원본 대조로만.
- 앱(아이폰/안드로이드)과 웹이 다르게 동작하는 분기(UA 감지) — 애플 5.6 이력. 기능 유무 감지만.
- 라이브 DB 에 가짜 기록·가짜 크루를 넣는다 — 시험은 에뮬레이터/로컬 하네스.
- 화면 문구에 "동아리" — 앱 안은 전부 "크루". 홍보 문구 "무료" 금지(단 "무료 PT"는 대표 지정 문구).
- 원화 표기, 이모지, 틴트 칩.

## 3. 제약

- 단일 `index.html`(4만 줄) + Firebase. Functions 는 Node 22(`functions/`), 리전 asia-northeast3.
- 머피 잔액은 클라이언트가 늘릴 수 없다(C2) → 지급은 서버(Functions)만. 장부 `ledger` 에 같이 남긴다.
- 휴면 `crews` 컬렉션은 규칙이 느슨하다(로그인만 하면 수정 가능) — **새 컬렉션 `crewsV2`** 를 쓰고 옛 것은 손대지 않는다.
- 체크인은 클라이언트가 GPS 를 재고 직접 쓴다(서버 검증 H5 는 출시 후 과제). 크루 출석은 이 기록을 그대로 믿는다 —
  한계로 대표에게 보고했고 이번 범위에서 고치지 않는다.
- 제미나이 키는 Secret Manager `GEMINI_API_KEY`(얼굴 생성과 공용). 유료 계정이어야 한다(무료 등급은 데이터가 학습에 쓰임).
- 스트라바 API 데이터는 AI 에 넣으면 안 되지만, 사용자가 올린 캡처는 API 데이터가 아니다.

## 5. 흐름

### 5.1 크루 만들기·가입·탈퇴
- 관리자 화면(기존 관리자 메뉴 안)에서 크루 생성 → `crewsV2` 문서 + `private/join.code`(6자리) → 초대 링크
  `https://murpy.app/?crew={id}&c={code}` 복사.
- 링크로 들어오면 크루 소개 시트 → [가입] → callable `crewJoin({crewId, code})` 가 코드 확인 후 members 문서·
  users.crewIds·stats.members 를 갱신. 비로그인/임시계정이면 기존 `memberGate()` 로그인 팝업.
- 탈퇴 = callable `crewLeave({crewId})` → members.left=true(문서는 남긴다), users.crewIds 에서 뺌, stats.members -1.
  다시 가입하면 left=false 로 되살리고 그동안 기록은 그대로.

### 5.2 러닝 인증샷 (1차)
1. 크루 페이지 또는 내 기록 화면의 [러닝 기록 올리기] → 사진 고르기(캡처). 앱 안 카메라 아님(카드 캡처라서).
2. 기존 업로드 경로(`uploadImgbb` = Storage `uploads/{uid}/`)로 올리고 callable `runSubmit({url})`.
3. 서버(runSubmit):
   - URL 이 우리 버킷의 `uploads/{uid}/` 인지 확인 → 내려받아 sha256. 같은 해시가 이미 있으면 거절("이미 올린 카드").
   - 제미나이 2.5 Flash-Lite 에 이미지 + JSON 스키마로 읽기: { isRunCard, app, km, sec, paceSec, dateText, dateISO }.
   - 거르기(거절 사유와 함께 돌려줌, 저장 안 함): 러닝 카드 아님 / 거리 0.5~100km 밖 / 페이스 2:30~15:00/km 밖 /
     거리×페이스≈시간(±12%) 불일치 / 카드 날짜가 7일보다 오래됨 / 같은 사람·같은 날·같은 거리·같은 시간 기록 이미 있음.
   - 카드에 날짜가 없으면 올린 날로 기록하고 `dayFromCard:false`.
   - 통과 → `runs` 문서(status 'unverified') + `runStats` 갱신. 크루 점수엔 안 들어감(미인증).
   - 2차부터: 앱이 건강 앱 운동 기록을 같이 보내면 시각·거리 대조 → 'verified' → 크루 합산·챌린지·10머피.
     이 대조 로직은 1차에 함수로 만들어 두고(입력 없으면 건너뜀) 단위 시험만 한다.
4. 화면: 카드 이미지 위로 스캔선이 훑고(약 1.5초 + 서버 응답 대기) 항목이 하나씩 체크 — 거리 → 페이스 → 날짜.
   결과: "미인증 · 개인 기록에 저장됐어요 — 건강 앱 연결이 열리면 인증돼요"(문구 확정 전). 거절이면 사유.

### 5.3 헬스 출석
- Firestore 트리거 `onDocumentCreated('checkins/{id}')` → 그 사람의 소속 크루마다 members.lastAttendDay 가 오늘이 아니면
  attends +1(멤버·크루·이번 달), 이번 주 참여 표시, 진행 중 'gym_attend' 챌린지 progress +1.
- 같은 날 두 헬스장을 찍어도 크루 출석은 1회.
- 성주: 같은 트리거에서 `centerMonth/{center}_{YYYYMM}.counts[uid]` +1, top 갱신. 체크인 화면에 "이번 달 성주 ○○ · n회".

### 5.4 챌린지
- 관리자가 크루 페이지에서 만든다: 종류, 시작일(기본 다음 월요일 00:00 KST), 14일, 1인 목표(기본 러닝 15km / 헬스 6회).
  target = 1인 목표 × 그 순간 멤버 수(고정).
- 진행: 인증된 러닝(run_km) / 크루 출석(gym_attend)이 기간 안에 들어오면 서버가 progress 증가.
- target 도달 → status 'done', 멤버 전원(그 순간 left=false) 에게 `CREW_CHALLENGE_REWARD` 머피 지급(ledger 키 = chId, 중복 불가),
  notifications 'crew_challenge_done'(멤버 전원 + 관리자). 기간 끝날 때까지 못 채우면 매시 스케줄러가 'failed'.
- 화면: 진행 막대(골드 아님, 블루), "PT 3회 추가까지 ○○km".

### 5.5 마일스톤
- 크루 누적(인증) km 가 100·500·1,000 을 처음 넘을 때 → milestones 에 추가, 그 순간 멤버 전원 users.titles 에
  "{크루명} 100km" 류 칭호 대신 **고정 칭호 3종**("크루 100K"·"크루 500K"·"크루 1000K") 을 준다
  (칭호 목록 `_mwTitleDefs` 가 고정 목록이라 이름이 크루마다 바뀌면 검증을 못 탄다).

### 5.6 숫자(설정값 한 곳 — `CREW_CFG`, 서버도 같은 값)
- 인증 1회 10머피(`run_verified`, 하루 상한 3회) · 건강 앱 첫 연결 100머피(2차) · 챌린지 달성 멤버당 `CREW_CHALLENGE_REWARD`
  (대표 미정 — 임시 30, 보고에 묻는다) · 마일스톤 100/500/1,000km · 러닝 1인 15km · 헬스 1인 6회 · 기간 14일.

## 6. 화면 위치(내 판단 — 배포 전 캡처로 확인받는다)
- **스쿼드 탭 맨 위**에 "내 크루" 줄(소속 크루가 있을 때만, 없으면 아무것도 안 보임 — 일반 유저에게 새 버튼을 밀지 않는다).
  누르면 크루 페이지(panel). 크루가 여러 개면 가로 칩 대신 목록.
- 크루 페이지 안에 [러닝 기록 올리기](러닝/혼합 크루) — 1차 입구는 여기 하나.
- 내 기록: 크루 페이지의 "내 기록" 영역 + 프로필 화면에 한 줄(누적 km · 인증 n회). 머피월드 방 전시는 2차 이후.
- 성주: 체크인 화면(헬스장 고른 뒤 도장 찍기 전 시트)에 한 줄.
- 관리자: 기존 관리자 메뉴에 "크루 관리"(만들기·초대 링크·챌린지 만들기).
- 스타일: 블루=액션, 골드=머피/칭호, Pretendard, 라인 SVG 아이콘, 틴트 칩 금지, 넓은 PC 창에서 숨김 요소 visibility 처리.

## 7. 검증
- Functions: `runSubmit` 거르기 규칙·대조 함수·챌린지/마일스톤/성주 계산을 순수 함수로 빼고 node 단위 시험.
  제미나이 호출은 실제 카드 캡처 몇 장(스트라바·나이키 공개 예시 이미지)으로 로컬 1회 확인.
- 웹: playwright 하네스로 가짜 데이터 주입해 화면 캡처(DPR3) — 라이브 DB 쓰기 없음.
- 배포 전: 브랜딩 세션에 캡처·문구 보내고 확인받기 → 규칙·함수·웹 순서로 배포.

## 8. 검토에서 나온 질문과 정리(내 판단 — 대표 확정 사항과 충돌 없음)
1. **1차 러닝 크루 숫자가 0** — 대표 확정 2(가) "미인증으로만 쌓고 대기"대로 크루 점수·챌린지·마일스톤은 인증만.
   대신 크루 페이지가 텅 비지 않게 **"인증 대기 n km · n회"** 줄을 따로 보여준다(점수 아님, 표시만).
   멤버·크루 문서에 `pKm`/`pRuns`(미인증 누적, 표시용)를 같이 둔다. `run_km` 챌린지는 만들 수 있지만 관리자 화면에
   "건강 앱 인증이 열린 뒤 시작 권장" 안내. 이번 주 참여(weekActive)·순위·대결 점수는 **인증 기준**, 프로필의 "인증 n회"도 인증만.
2. **배포 동결 여부** — 아이폰 1.0.1 은 10-14 출시 완료, 1.0.2 는 제출 안 함 → 심사 중 아님. 배포 전 ASC 상태만 한 번 확인.
3. **종목별 집계** — 모든 크루가 km 와 출석을 둘 다 쌓는다(러닝 크루원이 헬스장을 찍어도 출석은 쌓임). 화면의 주 지표는
   sport 로: running=km, gym=출석, mixed=탭으로 둘 다. 챌린지 종류는 관리자가 고른다.
4. **관리자** — 1차는 머피 운영자(`isAdmin`)만 크루·초대 링크·챌린지를 만든다. 크루 회장 권한은 다음 단계.
   달성 알림의 "관리자" = 운영자 계정.
5. **러닝 기록 공개·삭제** — `runs`·`runStats` 는 **로그인한 사람만** 읽기. 본인은 자기 기록을 지울 수 있다(callable
   `runDelete`): 개인 숫자 되돌림, 인증된 기록이면 크루 숫자도 되돌림(이미 달성 처리된 챌린지는 그대로). 올리기 화면에
   "지도에 집이 보이면 스트라바 개인정보 구역을 켜고 올려 주세요" 한 줄. 탈퇴(`deleteMyAccount`) 시 내 runs 와 카드 이미지 삭제,
   크루 members 는 left 처리.

## 9. 빌더에게 맡기는 것

- 스케줄러 주기(1시간 권장), 인덱스 정의.
