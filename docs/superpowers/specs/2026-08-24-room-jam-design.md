# 같이 낙서 + 카펫/액자 — 설계

2026-08-24 · 머피룸 초대 3단계 (1·2단계는 배포 완료)

## 무엇을 만드나

방에 모인 사람들(최대 4명)이 **같은 판에 동시에** 32×32 도트를 찍는다.
다 그리면 방 주인이 **바닥 카펫**이나 **벽 액자**로 방에 남긴다. 남긴 건 가구라서
꾸미기에서 옮기고 치울 수 있고, 개수 제한이 없다.

### 이미 있는 것 (새로 안 만든다)

| | 어디 |
|---|---|
| 판·팔레트·액자 CSS | `index.html` `#mw-jam` / `.mw-artframe` / `#mw-artbig` |
| 탭 버튼 | 월드바 `mw-wb-tabs` 의 「같이 낙서」 — 지금은 `showToast('곧 열려요')` + opacity .45 |
| **RTDB 규칙** | `database.rules.json` 의 `roomLive/$owner/jam` — `open`(주인만) · `px`(로그인) **배포 완료** |
| 방 실시간 | `roomLive/{주인}/players` presence · `_mwRlJoin` / `_mwRlLeave` / `_mwRlRender` |
| 가구 배치 | `room.f` 배열 · `mwFurnHtml` · `_mwFurnZ` · flat/wall 판정 · 꾸미기 드래그 |

## 왜 이렇게 정했나 (결정과 근거)

**동시에 같은 판** — 턴제·분할도 검토했으나, 방은 이미 같이 움직이고 말풍선을 띄우는
공간이라 낙서만 순서를 기다리게 하면 결이 어긋난다. 서로 덮어 그리는 장난이 재미다.

**바닥 카펫이 기본, 벽 액자는 선택** — 벽 액자는 캐릭터 **뒤**라 같이찍기 폴라로이드에
작게 걸치지만, 카펫은 캐릭터가 **그 위에 올라서** 있어 사진 한가운데 깔린다.
방바닥은 원근이 없는 평행 마룻바닥이라(`char/fields/field_room.png` 실측) **정사각을 그대로
깔면 정사각으로 보인다** — 눌러 그리거나 판을 가로로 길게 만들 필요가 없다.

**이미지 업로드를 안 탄다** — 32×32 한 칸을 글자 하나로 적으면 그림 한 장이 **글자 1024개**다.
사진의 1/500이라 Firestore 문서 필드에 문자열로 그냥 들어간다. 앱의 사진 업로드가
imgBB 한 곳에 전부 걸려 있고 8-19에 그게 멈춰 전 유저 인증이 죽은 적이 있는데,
낙서는 그 줄에 안 선다.

**프레임을 캔버스가 직접 그린다** — 그림 위에 액자 CSS를 덧씌우지 않는다.
같이찍기 폴라로이드에서 카드와 프레임 구멍이 어긋나 `from Murpy` 가 잘려나간 사고가
있었다(8-21). 한 장으로 구우면 두 겹이 어긋날 일 자체가 없다.

**티셔츠 프린트는 접었다** — 아래 "검토했고 접은 것" 참조.

## 데이터 모델

### 그림 (Firestore)

```
users/{uid}.room.art = {
  "<artId>": { px: "0011200…(1024자)", by: ["현수","민지"], at: 1756000000000 }
}
users/{uid}.room.f = [ …기존 가구…,
  { id: "art_rug",   x: 240, y: 300, a: "<artId>" },   // 바닥 카펫
  { id: "art_frame", x: 120, y:  60, a: "<artId>" }    // 벽 액자
]
```

- `px` — 한 글자가 한 칸. `'0'`=빈칸, `'1'`~`'6'`=팔레트 색. 좌→우, 위→아래 순서
- `artId` — `Date.now().toString(36)` + 랜덤 3자
- `by` — **걸 때 방에 있던 사람들**의 닉네임. RTDB `players` 를 그대로 읽는다
  (누가 어느 칸을 찍었는지는 기록하지 않는다 — 그걸 남기려면 RTDB 규칙을 고쳐야 하고,
   "같이 있었던 사람"이 서명으로 더 자연스럽다)
- 한 장 ≈ 1.1KB. 20장 걸어도 users 문서에 22KB. 방을 열 때 users 문서는 **어차피 읽으므로
  추가 읽기가 0**이다 (하위 컬렉션으로 빼면 액자 수만큼 읽기가 늘어난다)

### 판 (RTDB, 규칙 이미 있음)

```
roomLive/{주인}/jam/open = { at, by }        // 방 주인만 쓴다
roomLive/{주인}/jam/px/{0..1023} = 1..6      // 로그인이면 쓴다. 지우개 = null
```

## 구성 요소

### 1. 판 (`#mw-jam`)

전체화면. 위에서부터 판(320px 정사각 + 32칸 눈금) · 팔레트 · 안내 · 하단 버튼.

- **팔레트 7칸** = 색 6 + 지우개 1 (`.jam-pal` 이 `repeat(7,1fr)` 이라 그대로 맞는다)
  검정 `#14161E` · 흰색 `#F2F5FA` · 빨강 `#E4472E` · 노랑 `#F5C24B` ·
  초록 `#4ADE80` · 파랑 `#3D7EFF` — 색을 늘리려면 CSS 한 줄(`repeat(8,1fr)`)만 고치면 된다
- **찍기** — `pointerdown`/`pointermove` 로 끌어 그린다. `.jam-wrap` 에 `touch-action:none` 이
  이미 걸려 있다. 좌표 → 칸번호 = `(y/판높이*32|0)*32 + (x/판너비*32|0)`
- **하단 버튼** — 방 주인: `카펫으로 깔기` · `액자로 걸기` · `판 비우기` · `닫기`
  / 손님: `닫기` 만
- **남이 찍으면 살짝 반짝** — 받은 칸에 120ms 하이라이트. 같이 그리고 있다는 유일한 신호다

### 2. 실시간 동기화

- **보내기** — 로컬은 즉시 그리고, 전송은 **80ms 배치**로 모아 `update({'px/12':3,…})`.
  획마다 왕복하면 손가락보다 느리게 보이고, 안 모으면 요청이 폭주한다
- **받기** — 처음 한 번 `get(jam/px)` 로 전체를 받아 그리고, 그 뒤로는
  `onChildAdded` / `onChildChanged` / `onChildRemoved` 로 **바뀐 칸만** 받는다.
  `onValue` 로 전체를 매번 받으면 칸 하나 찍을 때마다 최대 10KB가 오간다
- **필요한 import** — `onChildAdded, onChildChanged, onChildRemoved` (firebase-database).
  `window._rt` 래퍼에 같이 실어야 모듈 밖에서도 쓴다

### 3. 판 열기 / 닫기

- **방 주인**이 「같이 낙서」 탭을 누르면 `jam/open` 을 쓰고 판이 열린다.
  **혼자 있어도 열 수 있다** — 그리다가 부르면 된다(초대는 같은 화면에 있다)
- **손님**이 탭을 누르면: 판이 열려 있으면 참여하고, 안 열려 있으면
  `방 주인이 시작할 수 있어요` 토스트. 손님은 `open` 을 못 쓴다(규칙이 막는다)
- 판이 켜지면 손님 화면에서 판이 **자동으로 열린다**. 닫기는 자유다.
  (참여 버튼을 한 번 더 누르게 하면 "같이"가 시작되기 전에 흩어진다)
- 판이 열려 있는 동안 탭 버튼에 라이브 점을 켠다 (`mw-wb-live` 재사용)
- **정리** — 걸거나 비우거나 방을 나가면 `jam` 을 통째로 지운다.
  방 주인이 없는데 판만 남는 상황을 만들지 않는다

### 4. 카펫 / 액자 (가구로 편입)

`ROOM_ITEMS` 에 정의 2개를 더한다. **`hidden:true` 라 상점·꾸미기 목록에는 안 뜬다** —
사서 놓는 물건이 아니라 그려서 생기는 물건이다.

```js
{ id:'art_rug',   name:'같이 낙서 카펫', w:288, h:288, flat:true, art:true, hidden:true, price:0 }
{ id:'art_frame', name:'같이 낙서 액자', w:96,  h:96,  wall:true, art:true, hidden:true, price:0 }
```

- 카펫 288 = **6×6 타일**(방 768 기준 37.5%). 캐릭터 서넛이 같이 올라선다
- `flat:true` → 밟고 지나가고, 접지 그림자를 안 그리고, 벽 클램프에서 빠진다 (이미 있는 판정)
- `wall:true` → 벽에 붙고 그림자가 없다 (이미 있는 판정)
- `mwFurnHtml` 은 `def.art` 이면 `def.src` 대신 **그려서 만든 dataURL** 을 쓴다.
  나머지(좌표·z·드래그·저장)는 전부 기존 경로 그대로다

### 5. 그림 → 이미지 (`mwArtImg`)

`px` 문자열과 종류(`rug`/`frame`)를 받아 dataURL 을 돌려준다. **프레임까지 캔버스가 그린다.**

- 카펫 — 그림 32×32를 8배(256px)로 찍고, 둘레에 **얇은 어두운 테두리 + 양옆 짧은 술**.
  테두리가 주인공이 되면 안 된다(8-24에 갈색 나무 띠가 그래서 반려됐다)
- 액자 — 그림을 6배(192px)로 찍고, 둘레에 나무 테두리 + 안쪽 매트
- 정수배로만 확대한다 (`imageSmoothingEnabled=false`)
- 같은 `artId` 는 **한 번만 굽고 캐시**한다. 방을 다시 그릴 때마다 굽지 않는다

### 6. 크게 보기 (`#mw-artbig`)

카펫·액자를 누르면 그림이 크게 뜨고 아래에 **`현수·민지가 같이 그렸어요`** 와 날짜.
남의 방을 구경할 때도 눌린다.

## 걸리는 곳

| 파일 | 무엇 |
|---|---|
| `index.html` | 판 UI·동기화·굽기·가구 정의·`mwFurnHtml` 분기·탭 버튼 활성화 |
| `index.html` (import) | `onChildAdded`/`onChildChanged`/`onChildRemoved` + `_rt` 래퍼 |
| `sw.js` + `_SW_V` | 버전 올리기 |

**안 건드리는 것** — `database.rules.json`(규칙 이미 있음) · `firestore.rules`
(`users/{uid}` 는 본인 쓰기라 `room.art` 가 그대로 통과) · 에셋(한 장도 안 든다)

## 검증

폰에서 확인해야 하는 것 (내 미리보기로는 증명이 안 된다):

1. 방 주인이 판을 열면 **손님 폰에도** 판이 뜨는가
2. 두 폰에서 동시에 찍을 때 서로 보이는가. 얼마나 늦는가
3. 카펫으로 깔면 방에 나타나고 **캐릭터가 그 위를 걸어다니는가**
4. 액자로 걸면 벽에 붙는가. 가구로 가려지는가
5. 꾸미기에서 옮기고 치울 수 있는가
6. 같이찍기 사진에 카펫이 찍히는가
7. 방을 나갔다 들어와도 남아 있는가

## 검토했고 접은 것

### 티셔츠 프린트 (2026-08-24)

그린 걸 캐릭터 옷에 박아 들고 다니자는 안. **크기 때문에 접었다.**

캐릭터는 원본 141×224인데 방에서는 가로 44px로 그려진다(타일의 3.3배).
그 안에서 가슴팍은 **약 12px** — 폰에서 3mm다.

| 어디서 | 가슴 프린트 | |
|---|---|---|
| 방에서 걸어다닐 때 | **12px** | 하트·이니셜 정도만. 그림은 못 알아봄 |
| 폴라로이드 사진 | 33px | 보이긴 함 |
| 캐릭터 정보 창 | 60px | 잘 보임 |
| 꾸미기 화면 | 77px | 아주 잘 보임 |

꾸미기에서 열심히 그려놓고 방에 나가면 색점 하나가 된다. 같은 그림이 카펫에서는
화면 135px — **면적으로 120배** 크고 사진에도 한가운데 깔린다.

방향(좌/우/뒤)은 걸림돌이 아니었다. 정면에만 얹고 옆·뒤는 안 보이게 하면 자연스럽고,
걷는 프레임마다 흔들리는 것도 정면 4프레임의 가슴 좌표만 재두면 된다.
**순전히 크기 문제다.**

되살린다면 조건: 그림을 줄여 붙이지 말고 **처음부터 12×12로 그리게** 하고,
"그림"이 아니라 **도장·이니셜·하트 같은 단순 심볼** 용도로 한정할 것.

### 그 외

- **현수막·깃발** — 세로형이라 정사각 도트와 안 맞는다
- **문 앞 도어매트** — 너무 작아 그림이 안 보인다
- **벽지 전체 교체** — 배경을 갈아끼워야 해서 방 시스템을 흔든다
- **`onValue` 전체 구독** — 칸 하나 찍을 때마다 최대 10KB. RTDB 무료 한도를 갉아먹는다
- **하위 컬렉션(`users/{uid}/art/{id}`)** — 방 열 때 액자 수만큼 읽기가 늘어난다.
  방 문서 안에 두면 추가 읽기가 0이다
