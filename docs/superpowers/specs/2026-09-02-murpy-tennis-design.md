# 머피 테니스 — 설계

작성 2026-09-02 · 상태: 대표 검토 대기(주무시는 동안 작성, 아침에 확인)

대표 지시(9-02 새벽): "골프게임 최적화 다하면 뭐 테니스 같은거 게임만들어도되고",
"테니스게임도 너가알아서 슈퍼파워써서 계획해서만들어놔".
질문에 답해 주실 수 없는 상태라 **아래 '내가 대신 판단한 것' 절에 가정을 모두 적어 둔다.**

---

## 1. 왜 이것인가 — 자리가 이미 비어 있다

머피월드 필드 목록에 **`tennis` 필드가 이미 있다**(`char/fields/field_tennis.png`, 1024×1024).
네트·벤치·공바구니까지 그려진 제대로 된 탑다운 코트인데 **게임만 없다.**

```
gym    → 덤벨 피하기   (mw-fieldchip → dodgeOpen)
golf   → 홀인 머피     (mw-fieldchip → golfOpen)
tennis → (없음)        ← 여기
```

즉 새 자리를 만드는 일이 아니라 **비어 있는 세 번째 칸을 채우는 일**이다.
명예의 전당도 9-02에 '게임' 탭 하나로 묶고 그 안에서 종목을 고르게 바꿔 뒀으므로
(`window.HOF_GAMES`), 종목 하나가 늘어날 자리가 이미 준비돼 있다.

## 2. 무엇을 만드는가

**머피 테니스** — 1인용 랠리 게임. AI 상대와 랠리를 주고받으며 점수를 낸다.

### 조작은 탭 하나뿐이다
- 공이 내 코트로 넘어온다 → **임팩트 존**에 들어왔을 때 화면을 탭한다.
- **탭한 x 위치가 받아칠 코스**가 된다. 왼쪽을 누르면 왼쪽으로, 오른쪽을 누르면 오른쪽으로 친다.
- 캐릭터는 공을 따라 **자동으로** 좌우 이동한다. 이동을 손으로 하지 않는다.

한 손 엄지로 되는 조작이면서, "어디를 누르는가"가 전략이 된다.
상대를 한쪽으로 몰아 놓고 반대편을 찌르면 상대가 못 따라가 **득점**한다.

### 이기고 지는 법
- 타이밍을 놓치거나(임팩트 존 밖에서 탭) 아예 안 치면 **실점**.
- 코스가 라인 밖으로 나가면 실점(너무 가장자리를 노리면 아웃).
- 상대가 못 받으면 **득점**.
- **3실점이면 종료.** 점수 = 득점 × 100 + 최장 랠리 × 10.

## 3. 왜 이 장르인가 — 기존 두 게임과 겹치지 않게

| 게임 | 장르 | 조작 |
|---|---|---|
| 덤벨 피하기 | 반사신경(회피) | 좌우 이동 |
| 홀인 머피 | 정확도(게이지) | 3탭 게이지 |
| **머피 테니스** | **리듬 + 수 싸움** | **탭 1개(위치가 코스)** |

검토했다가 버린 안:
- **좌우 이동 + 스윙(진짜 테니스에 가깝게)** — 입력이 둘이라 폰 한 손에 무리다.
  덤벨의 이동과 골프의 스윙을 섞으면 둘 다 아닌 것이 된다. 기각.
- **서브 표적 맞추기** — 게이지로 파워·방향을 정하는 구조라 홀인 머피와 거의 같다. 기각.

## 4. 구조 — 새 뼈대를 만들지 않는다

골프는 덤벨 피하기 마크업을 그대로 복사해 id 만 바꿨다(8-30 대표 지적: 배치·버튼 크기가 달랐다).
**테니스도 같은 뼈대를 쓴다.** 새 UI 문법을 만들지 않는다.

```
#tennis-screen  (전체화면 오버레이)
  ├ #tennis-pane-title   타이틀 그림 + [시작]
  ├ #tennis-pane-howto   설명
  ├ #tennis-pane-char    난이도 선택 (하/중/상)
  ├ #tennis-field        경기 화면
  └ #tennis-over         결과 + 공유
```

- 진입: `tennis` 필드의 `.mw-fieldchip` → `window.tennisOpen()`
- 저장: `users/{uid}.games.tennis.{best, plays, recent, lastAt}` — 덤벨·골프와 **같은 모양**
- 명예의 전당: `HOF_KINDS.tennis` 추가 + `HOF_GAMES` 배열에 `'tennis'` 한 줄
- 공유: 새로 만들지 않는다. `_mwStampData` 에 카드 그림만 넣으면 카톡·인스타·저장이 그대로 돈다
- 캐릭터 렌더: `_charRenderTo` 하나만 쓴다(새 렌더 경로를 만들면 조합 규칙이 빠져 그 화면만 깨진다)

### 판정은 순수 함수로 분리한다
`window._tennisJudge(state, tapX, now)` → `{ result:'hit'|'late'|'early'|'out', course, power }`

이유: 이 게임은 **대표가 자는 사이 만들어져 아침에 처음 켜진다.**
"쳤는데 안 맞는다 / 안 쳤는데 넘어간다" 류는 폰으로 돌려도 원인을 못 찾는다.
옆 세션이 무궁화꽃에서 같은 이유로 `_sqMgJudge` 를 분리하고 테스트 11개를 붙였다 — 그 방식을 따른다.

## 5. 화면

탑다운 코트를 **세로로** 쓴다. 내 코트가 아래, 상대 코트가 위, 네트가 가운데.
`field_tennis.png` 를 배경으로 깔고 그 위에 캐릭터·공·그림자를 얹는다.

- 논리 좌표 0~100 × 0~100. 네트 y=50. 내 베이스라인 y=88, 상대 y=12.
- **임팩트 존** = 내 캐릭터 주변의 가로 띠(y 78~92). 공이 이 안에 있을 때 탭해야 맞는다.
- 공은 포물선으로 난다 — z 높이를 따로 들고 그림자를 바닥에 그린다(골프와 같은 방식).
- 타이밍 표시: 공이 임팩트 존에 가까워지면 캐릭터 발밑에 링이 좁혀진다. 링이 가장 작을 때가 완벽.

★골프에서 배운 것: **예측선은 공식이 아니라 같은 물리를 미리 돌린 결과여야 한다.**
여기서도 링의 타이밍은 실제 공 궤적을 그대로 써서 계산한다. 어긋나면 유저는 "판정이 이상하다"고 느낀다.

## 6. 난이도

기존 두 게임과 같은 하/중/상. 대표 8-30 지시: "난이도마다 차별점이 확실해야 한다."

| | 상대 속도 | 공 속도 | 임팩트 존 | 아웃 판정 | 점수 배율 |
|---|---|---|---|---|---|
| 하 | 느림 | 느림 | 넓다 | 관대 | ×0.7 |
| 중 | 보통 | 랠리마다 조금씩 빨라짐 | 보통 | 보통 | ×1.0 |
| 상 | 빠름 | 더 빨리 빨라짐 | 좁다 | 엄격 | ×2.5 |

## 7. 에셋

새로 필요한 것은 **공과 타이틀 두 개뿐**이다. 나머지는 있는 것을 쓴다.

| 쓸 것 | 어디서 |
|---|---|
| 코트 배경 | `char/fields/field_tennis.png` — **이미 있다** |
| 내 캐릭터 | `_charRenderTo` — **이미 있다** |
| 상대 | **내 캐릭터와 같은 `_charRenderTo`** 로 그리되 색만 다른 옷을 입힌다. 새 시트를 만들지 않는다 |
| 공 | **CSS 원 + 그림자**로 그린다. 화면에서 8~10px 짜리라 그림을 만들 값이 없다 |
| 타이틀 | 새로 생성 — `char/game/tennis_title.png` (덤벨·골프와 같은 방식) |

에셋 신규는 **타이틀 하나뿐**이다. 공을 CSS 로 그리는 이유는 크기 때문이다 —
두더지가 10×7px 로 그려져 안 보였던 것처럼, 8px 짜리는 그림을 넣어도 도트 두세 개로 뭉갠다.

★에셋을 만들면 **캔버스 채움률을 반드시 잰다.** 9-02 골프 두더지가 누끼로 몸통이 지워져
불투명 픽셀 1%만 남았고 화면에 10×7px 로 그려졌다 — 대표가 한 번도 못 봤다.
정상 스프라이트는 캔버스를 91~100% 채운다.

★`char/` 는 지금 옆 세션(system32-40)이 술래·관장 시트로 쓰고 있다.
테니스 에셋은 `char/game/tennis_*.png` 로만 만들고 다른 파일은 건드리지 않는다. 만들기 전에 알린다.

## 8. 내가 대신 판단한 것 (대표 확인 필요)

주무시는 동안 진행하느라 아래는 **내가 정했다.** 아침에 아니라고 하시면 바꾼다.

1. **1인용으로 만든다.** 스쿼드 멀티(OX 퀴즈·무궁화꽃)가 아니라 덤벨·골프와 같은 혼자 하는 게임.
   근거: 명예의 전당 '게임' 탭은 개인 최고점 랭킹이고, 대표가 "게임탭 안에 덤벨피하기, 골프 등등"
   이라고 하셨다 — 테니스를 그 목록의 세 번째로 지목하신 것으로 읽었다.
2. **조작은 탭 하나.** 이동은 자동. 근거: 폰 한 손 조작 + 기존 두 게임과 장르 분리.
3. **3실점 종료.** 근거: 한 판이 1~2분이어야 다시 누른다(덤벨·골프와 같은 호흡).
4. **점수 = 득점×100 + 최장랠리×10.** 랭킹에 올릴 하나의 숫자가 필요하고, 득점만 세면
   랠리를 길게 끄는 재미가 점수에 안 잡힌다.
5. **상대는 AI 한 명.** 사람 대전은 실시간 동기화가 필요해 이번 범위 밖.

## 9. 하지 않는 것 (YAGNI)

- 사람 대 사람 대전 · 토너먼트 · 시즌
- 라켓/코트 꾸미기 아이템
- 복식
- 세트·게임·듀스 같은 실제 테니스 점수 체계 — 배우는 데 시간이 걸려 첫 판에서 튕겨 나간다

  난이도별 존 너비 / 랠리 가속 후에도 판정이 일관 / 탭 x 가 코스로 바르게 매핑
