# 덤벨 피하기 (헬스장 필드 1인 미니게임) — 설계

작성 2026-08-19 · 대표 승인(브레인스토밍 8-19)

## 1. 왜 만드는가

대표 원문:

> "미니게임천국처럼 약간 헬창버전 미니게임천국을 만들면 어떨까."
> "범프의 경우 스쿼드가 만들어지고 실제 만남이 이루어지기 전까지 이탈이 많아질 확률이 높다고 봄."

범프가 *오프라인* 아하 모먼트라면, 미니게임은 **만나기 전까지 앱에 남을 이유**다.

## 2. 셋 중 이것부터 하는 이유

같이 나온 아이디어는 셋이다([[project_murpy_field_artifact]]).
(a) 스쿼드 단체 게임 / (b) 명예의 전당 랭킹(**8-19 완료**) / (c) 필드별 1인 게임.

**(c) 를 (a) 보다 먼저 한다** — (c)는 혼자 도는 화면이라 RTDB 실시간 동기화가 없다.
여기서 만든 게임 루프(낙하·충돌·점수·종료)를 (a)가 그대로 쓴다.
(a)부터 하면 게임도 처음이고 실시간 동기화도 처음이라 두 개가 동시에 터진다.

**셋(헬스·테니스·골프) 중 헬스 하나만 만든다.** 조작이 셋 다 다르고(피하기/반사/당기기)
사실상 게임 세 개다. 재밌는지 보고 나머지를 정한다.

## 3. 게임 규칙 (대표 확정)

위에서 물건이 떨어진다. 좌우로 움직여 받거나 피한다.

| 떨어지는 것 | 결과 |
|---|---|
| **덤벨** | 맞으면 **즉시 종료** |
| **보충제** | 받아먹으면 **+10점** |
| **치킨** | 먹으면 **−15점** (죽지는 않는다) |

- 살아있는 동안 **+1점/초**
- 시간이 갈수록 낙하 속도·개수 증가
- 점수는 0 아래로 안 내려간다

★**치킨이 안 죽이는 게 핵심이다.** 덤벨만 있으면 피하기만 하는 반사신경 게임인데,
치킨이 붙으면 "보충제 옆 치킨을 먹을까 말까"라는 **판단**이 생긴다.

★**덤벨은 즉사다.** 목숨을 주면 긴장이 사라진다(똥피하기의 원형이 그렇다).

## 4. 조작 — 좌우만

**점프는 못 만든다.** `char/walk.png` 에 점프 프레임이 없고 base 시트 재수정은 하드룰 금지다.
그래서 **좌우 이동만으로 성립하는 규칙**만 넣었다 — 피하기·받아먹기가 정확히 그런 규칙이다.

화면 아무 데나 손가락을 대고 좌우로 끌면 캐릭터가 따라온다(필드 드래그 조이스틱과 같은 문법).
※필드는 탭투워크가 아니다 — 탭 경로가 앱에 없다.

## 5. 화면 — 별도 오버레이

**필드 걷기 로직을 건드리지 않는다.** 범프 화면(`#bp-*`)과 같은 전체화면 오버레이다.

★다른 창이 지금 헬스장 필드에 합판 히든 오브젝트를 넣는 중이다
(`_FIELD_SPOTS.gym.plate` tc 11~12 / tr 7, `_mwPlateHit`, `_PLATE_TAPS_*`).
**거기 손대면 충돌난다.** 필드에 닿는 것은 **시작 버튼 하나뿐**이다.

- 캐릭터는 기존 `mwMiniCharHtml` 로 그린다 — 새 렌더 경로를 만들지 않는다
  ([[feedback_murpy_char_render_one_path]]). 좌우 이동이라 `face`는 left/right 를 준다
- 낙하 물체는 DOM `<img>` + `transform: translate` 로 움직인다. Canvas 를 안 쓴다 —
  캐릭터가 DOM 레이어 합성이라 Canvas 로 옮기면 캐릭터가 두 벌이 된다
- 프레임은 `requestAnimationFrame`. 배경은 기존 헬스장 필드 그림을 그대로 깐다

## 6. 데이터

```
users/{uid}.games = { dodge: { best: <int>, plays: <int>, lastAt: <ms> } }
```

본인 문서라 보안규칙 변경이 없다(`allow write: if isOwner || isAdmin`).
**최고점만 갱신한다**(`best` 보다 높을 때만 쓴다) — 매 판 쓰면 쓰기가 낭비된다.
`plays`(총 판수)는 **'재밌는지'를 판정할 유일한 숫자**라 같이 센다 — 최고점만으로는
한 번 하고 안 돌아온 건지 매일 하는 건지 구분이 안 된다. 이건 매 판 올린다(정수 1 증가).

## 7. 명예의 전당 '게임' 탭 (대표 지정)

상단 탭에 **`게임`** 을 추가하고, **그 안에 게임별 탭**을 둔다.
지금은 덤벨 피하기 하나지만 나중에 테니스·골프가 붙을 자리가 미리 생긴다.

```
[인증] [체크인] [스쿼드장] [참가] [게임]
                              └ ( 덤벨 피하기 )
```

★탭이 5개가 되면서 `스쿼드 참가` 가 잘린다 → 라벨을 **`참가`** 로 줄인다.
★`HOF_KINDS` 에 한 줄 더하는 것으로 끝난다 — 랭킹 계산부·패널·팝업이 그대로 재사용된다.

## 8. 보상 = B + C (대표 확정)

- **B. 기록** — 위 '게임' 탭 랭킹. 상시 동기
- **C. 이달의 한정 오브젝트** — 점수 **`DODGE_GIFT_AT`** 을 넘기면 기존 시즌 상자
  (`SEASON_ITEMS` + `cond`)로 **1회** 지급. 첫 미끼이고, 계절마다 바뀌니 다음 달에 또 할 이유가 된다.
  ★**값은 대표가 실기기에서 몇 판 해본 뒤 정한다.** 지금 숫자를 지어내면 "한 판에 되거나
  영영 안 되거나" 둘 중 하나가 된다. 튜닝 상수(`DODGE`)에 같이 넣어 숫자만 바꿔 배포한다.
  첫 배포는 **`DODGE_GIFT_AT = 0`(꺼짐)** 으로 나간다 — 값이 정해지기 전엔 지급이 안 열린다

### ★머피는 안 준다

판정이 **전부 폰 안에서** 일어난다. 점수를 조작해 머피를 무한히 뽑는 걸 막을 방법이 지금 없다
(서버 검증이 없다). [[project_murpy_economy]] 에 *"돈 빠지는 자리엔 화면 게이트 말고 서버 확인"* 이
사고 기록으로 남아 있다. 게임이 재밌다고 판정되면 그때 서버 검증과 **함께** 붙인다.

### 조작 방어 (돈이 안 걸려도 최소한은 한다)

랭킹을 읽을 때 **말이 안 되는 점수는 버린다**(`DODGE_MAX = 9999`).
안 그러면 누가 한 번 큰 수를 써넣고 그 탭을 영구 점유한다. 랭킹은 남에게 보이는 자리다.

## 9. 에셋 (나노바나나) — 대표가 뽑는다

**설계 확정 후 프롬프트를 .txt 로 드린다.** 지금 주면 크기·프레임 수가 안 정해져 다시 뽑게 된다.

뽑을 것: **덤벨 · 보충제 · 치킨 · 맞았을 때 이펙트** (배경은 기존 헬스장 필드 재사용)

- 누끼용은 무조건 **`#00FF00` 형광 초록 단색 배경** — 나노바나나는 투명 배경을 못 그린다
  [[feedback_nanobanana_chroma_green]]
- 프롬프트는 **`.txt`**, 물체마다 **완결 블록**으로 [[feedback_prompt_files_are_txt]]
  [[feedback_prompt_give_full_version]]
- ★**회전 프레임을 만들지 않는다.** AI 도트 시트의 입체 소품은 프레임마다 어긋난다
  [[feedback_ai_dot_sheet_props]] → **정지컷 한 장**만 뽑고 회전은 CSS 로 돌린다

## 10. 안 하는 것 (YAGNI)

머피 보상 / 목숨·컨티뉴 / 아이템·파워업 / 멀티플레이 / 테니스·골프 게임 /
난이도 선택 / 일시정지.
→ **재밌는지 먼저 보고** 정한다.

## 11. 위험

1. **재미는 숫자로 못 정한다.** 낙하 속도·간격·물체 비율은 대표가 실기기에서 해보고 고쳐야 한다.
   → **튜닝 값을 상수 한 곳에 모아** 숫자만 바꿔 배포할 수 있게 한다(`DODGE` 객체)
2. **성능** — 저사양 폰에서 DOM 물체가 많으면 끊긴다. 화면에 **동시 12개**로 상한을 두고,
   화면 밖으로 나간 것은 즉시 지운다(재활용하지 않는다 — 12개면 생성 비용이 무시할 수준이다)
3. **다른 창과의 충돌** — 헬스장 필드는 지금 그 창이 만지고 있다. 시작 버튼 한 줄 외에는
   `_FIELDS`·`charMove`·`_FIELD_SPOTS` 를 건드리지 않는다
