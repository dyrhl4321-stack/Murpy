1. 플레이스토어 비공개 테스트 — 지금 관리해야 하는 것
-------------------------------------------------------------------------
현황: 대표가 테스터 명단을 CSV 로 사서 올려 테스트가 돌고 있음.
개인 개발자 계정은 [비공개 테스트 N명 · 14일 연속] 을 채운 뒤
[프로덕션 액세스 신청] → 구글 설문 심사를 통과해야 정식 출시가 열립니다.
(N 은 2025년에 20명→12명으로 완화. 정확한 숫자는 콘솔 문구가 진실.)

★관리 포인트 4가지 (14일 동안):

 1) 옵트인 인원 유지 — 콘솔 대시보드에서 "테스터 참여" 숫자를 이틀에 한 번 확인.
    테스터가 중간에 빠져 기준 밑으로 내려간 날은 14일에서 빠집니다(연속이 끊김).
    빠지면 채워 넣을 예비 인원(근방단)을 미리 확보해 두세요.

 2) ★참여도 — 가장 큰 거절 사유. 구글은 신청 설문에서
    "테스터를 어떻게 모았나 / 어떤 피드백을 받았나 / 무엇을 고쳤나"를 묻고,
    설치만 하고 아무도 안 쓴 흔적이면 거절합니다. **구매한 테스터는 설치만 하고
    안 여는 경우가 많아 위험** — 근방단 실사용자 몇 명을 같은 테스트 트랙에
    추가해서 실제 사용 기록을 만드는 것을 강하게 권합니다.

 3) 중간 버전 업데이트 — 14일 동안 AAB 를 1~2번 올리세요(활발한 개발 증빙).
    머피는 TWA 라 앱 내용은 웹 배포로 자동 반영되지만, **구글 콘솔에 보이는 건
    AAB 의 versionCode 뿐**입니다. 방법:
      pwabuilder.com 에 murpy.app 입력 → Android 패키지 → 패키지명 app.murpy.twa,
      versionCode 를 지금 것보다 크게 → **처음 만들 때 백업해 둔 같은 서명키**로 서명
      → 비공개 테스트 트랙에 업로드.
    ★서명키가 다르면 업로드가 거부되거나 주소창이 다시 뜹니다. 키 백업 필수.

 4) 설문 답변 준비 — 우리는 재료가 좋습니다. 그대로 쓸 수 있는 답 초안:
    · 모집: "운영 중인 오프라인 운동 커뮤니티(근방단, 247명)와 지인 네트워크에서 모집"
    · 피드백 반영: "테스트 기간에만 웹 업데이트 100회 이상(v801→v963), 유저 피드백
      22건 문서화·반영(체크인 GPS 정확도 개선, 키보드 가림 수정, 스쿼드 게임 추가 등)"
    · 출시 준비도: "결제 없음 · 계정삭제/차단/신고 구현 · 개인정보처리방침 게시"

콘솔에서 대표가 확인해서 알려줄 것 (제가 콘솔에 접근 못 합니다):
  □ 테스트 시작일 (14일 마감이 언제인지)
  □ 현재 옵트인 테스터 수 / 요구 인원 문구
  □ Play App Signing 사용 여부 — 사용 중이면 콘솔의 앱 서명 SHA256 지문이
    지금 게시된 assetlinks.json 지문(74:6E:04:...)과 같은지. 다르면 앱에 주소창이
    뜹니다 → 지문 알려주시면 제가 assetlinks.json 갱신합니다.
  □ 실기기에서 스토어 테스트 앱 설치 → 주소창 없이 뜨는지

    단순 웹뷰 아님"), 개인정보 라벨(8-29 문서 4번 표 그대로).
